In parole semplici — cosa studiamo qui
Vogliamo capire quanto «costa» un algoritmo al crescere dell'input, senza misurare secondi sul tuo laptop. Contiamo i passi elementari (assegnamenti, confronti, somme) e li riassumiamo con notazioni come O, Ω, Θ. 01Pingala: algoritmo lento vs algoritmo veloce

Il corso parte da due algoritmi per calcolare l'n-esimo numero di Pingala. È una sequenza simile a Fibonacci: P(1)=1, P(2)=2, P(3)=3, P(4)=5, P(5)=8… ciascun termine è la somma dei due precedenti. Confrontando i tempi su diversi linguaggi (Python, Java, C, Racket), emerge un fatto fondamentale:

Perché partire da Pingala?
I due algoritmi calcolano lo stesso risultato, ma uno impiega tempo esponenziale e l'altro lineare. È l'esempio perfetto per capire perché «stesso problema» ≠ «stesso costo».
Pingala(n) — ricorsivo naïve

Chiama sé stesso due volte per ogni n>2. Il numero di chiamate cresce esponenzialmente in n.

Complessità informale: esponenziale in n

Pingala-Inc(n) — iterativo

Un solo ciclo for da 3 a n. Ogni iterazione fa lavoro costante.

Complessità informale: lineare in n

Il grafico dei tempi mostra che Pingala-Inc scala linearmente con n, mentre Pingala esplode. Ma come caratterizziamo formalmente la complessità di un algoritmo?

Obiettivo dell'analisi
Vogliamo una misura che sia:
  • Specifica all'algoritmo — distingue Pingala da Pingala-Inc
  • Indipendente dall'implementazione — non dipende da Python vs C, da gcc -O2, ecc.
  • Predittiva — ci dice come scala il tempo al crescere dell'input
Pingala(n)                    ← versione lenta (ricorsiva)
if n ≤ 2
    return n
return Pingala(n−1) + Pingala(n−2)

Pingala-Inc(n)                  ← versione veloce (iterativa)
if n ≤ 2
    return n
pprev = 1;  prev = 2
for i = 3 to n
    P = prev + pprev
    pprev = prev;  prev = P
return P

02Il modello RAM (Random-Access Machine)

Il modello RAM è un modello informale ma standard del computer. Non modella cache, pipeline, parallelismo: conta solo i passi elementari eseguiti dall'algoritmo.

Analogia
Immagina di contare i passi di una ricetta, non i minuti sul forno. Ogni «mescola», «aggiungi», «controlla se» vale 1 passo. Non importa se usi forno a gas o elettrico: se una ricetta ha 10 passi e l'altra 1000, la seconda resta più lunga per porzioni grandi.

Tipi di base

  • Numeri interi e in virgola mobile
  • Ogni "parola" di dati ha dimensione limitata (es. 64 bit)

Passi elementari (basic steps)

CategoriaEsempiCosto nel modello
Load/Storeassegnamento x = 5, lettura di una variabile1 passo (costante)
Aritmeticaa + b, a * b, a / b1 passo
Branchif, while, salto condizionale1 passo
Chiamatainvocazione di una subroutine1 passo (+ costo del corpo)
Assunzione fondamentale
Ogni passo elementare richiede un tempo costante, dove "costante" significa indipendente dalla dimensione dell'input n. Il valore numerico di questa costante dipende dalla tecnologia (processore, linguaggio), ma non da n.
Perché un modello così semplice?
Il RAM model non pretende di predire i secondi esatti di esecuzione. Serve a confrontare algoritmi: se A fa Θ(n) passi e B fa Θ(n²) passi, B sarà più lento di A per n sufficientemente grande, indipendentemente dal processore.

03Analisi formale di Pingala-Inc nel modello RAM

Per analizzare un algoritmo nel modello RAM, costruiamo una tabella costo × volte: per ogni riga di pseudocodice indichiamo il costo ci (una costante) e quante volte viene eseguita in funzione di n.

Tabella completa (caso n > 2)
Pingala-Inc(n)             costo   volte
1  if n ≤ 2               c₁      1
2    return n              c₂      0      ← non eseguita se n>2
3  pprev = 1               c₃      1
4  prev  = 2               c₄      1
5  for i = 3 to n         c₅      n−1    ← test del for: i=3,4,...,n
6    P = prev + pprev      c₆      n−2    ← corpo: i=3,...,n (n−2 volte)
7    pprev = prev          c₇      n−2
8    prev  = P             c₈      n−2
9  return P               c₉      1
T(n) = c₁ + c₃ + c₄ + c₉ + (n−1)c₅ + (n−2)(c₆ + c₇ + c₈)

Espandendo e raggruppando i termini costanti:

T(n) = n·C₁ + C₂    dove C₁, C₂ sono costanti positive

Quindi T(n) è una funzione lineare di n.

Contare le volte del ciclo (es. n = 5)
Il for i = 3 to n con n=5 esegue i = 3, 4, 5 → il test del for viene fatto 3 volte (n−1). Il corpo (righe 6–8) gira solo per i=3 e i=4 → 2 volte (n−2), perché all'ultima iterazione (i=5) il test fallisce e si esce senza eseguire il corpo un'ultima volta. Questa distinzione è normale nell'analisi RAM.

Fattori costanti: perché li ignoriamo

Una domanda naturale: un'assegnazione (x = 0) costa meno di una somma (y + z)? In realtà sì, su hardware reale. Ma:

  • I costi specifici variano enormemente tra linguaggi, compilatori e processori
  • Semplifichiamo assumendo c₁ = c₂ = c₃ = … = ci (tutti uguali al costo massimo)
  • Questa semplificazione non cambia l'ordine di crescita asintotico
Conclusione
La complessità di Pingala-Inc è Θ(n). Ignoriamo le costanti moltiplicative e additive perché la tecnologia cambia, ma l'ordine di crescita (lineare vs quadratico vs esponenziale) resta invariante.

04Come misuriamo la complessità

Complessità come funzione della dimensione dell'input

In teoria T(n) usa n = dimensione dell'input in bit. In pratica, spesso usiamo un parametro naturale dell'istanza (lunghezza dell'array, numero di vertici, valore massimo…). Per Pingala-Inc l'input è il numero intero n: in bit occupa Θ(log n) cifre, ma il ciclo for i = 3 to n gira Θ(n) volte sul valore n — ed è quello che determina il costo. Le slide usano n in questo senso operativo.

Esempio — Find(A, x)
Find(A, x)
for i = 1 to length(A)
    if A[i] == x
        return true
return false

Se n = length(A), il ciclo esegue al massimo n iterazioni → T(n) = C·n → Θ(n) nel worst-case.

Worst-case complexity

In generale misuriamo la complessità nel caso peggiore (worst-case): il massimo numero di passi su tutti gli input di dimensione n.

Perché il worst-case?
Per Find(A, x), se x è il primo elemento fai 1 passo (best-case), se x è assente fai n passi (worst-case). Promettiamo un bound che vale sempre, anche per l'input più «cattivo» — così il cliente dell'algoritmo sa il costo massimo garantito.
Esempio — FindEquals(A)
FindEquals(A)
for i = 1 to length(A) − 1
    for j = i + 1 to length(A)
        if A[i] == A[j]
            return true
return false

Il ciclo interno per i=1 esegue (n−1) iterazioni, per i=2 esegue (n−2), …, per i=n−1 esegue 1.

Σi=1n−1 (n−i) = n(n−1)/2 = Θ(n²)

Nel worst-case (nessuna coppia uguale trovata prima della fine) → T(n) = Θ(n²).

Confronto 100n + 3000 vs 0.02n² + 2
Per n piccolo (es. n=10): il primo algoritmo costa ~4000, il secondo ~4. Il primo sembra peggio!
Per n grande (es. n=10000): il primo costa ~1.000.000, il secondo ~2.000.000.000. Il secondo domina.
Morale: per n sufficientemente grande, conta solo l'ordine di crescita, non le costanti.

05Complessità asintotica

Ci interessa il comportamento di T(n) quando n → ∞ ("per n sufficientemente grande"). Ignoriamo:

  • Termini di ordine inferiore (es. in n² + 10n + 100, ignoriamo 10n e 100)
  • Coefficienti moltiplicativi costanti (es. 5n² e n² hanno lo stesso ordine)

Questo ci porta alle notazioni asintotiche: O (upper bound), Ω (lower bound), Θ (tight bound).

06Notazioni O, Ω, Θ, o, ω

In parole semplici — O, Ω, Θ
Pensa a due funzioni f(n) e g(n) quando n diventa molto grande:
  • O(g) — «f non cresce più veloce di g» (limite superiore, come un tetto)
  • Ω(g) — «f cresce almeno come g» (limite inferiore, come un pavimento)
  • Θ(g) — «f cresce esattamente come g» (tetto e pavimento: bound stretto)
Esempio: 3n² + 100n è Θ(n²) perché il termine n² domina tutto il resto per n grande.

Definizioni formali

Big-O — upper bound
O(g(n)) = { f(n) : ∃ c > 0, ∃ n₀ > 0 : 0 ≤ f(n) ≤ c·g(n) ∀ n ≥ n₀ }

f(n) = O(g(n)) significa: f cresce al massimo come g. Esiste una costante c tale che f resta sotto c·g per tutti i n grandi.

Interpretazione: g è un upper bound (limite superiore) per f. g domina f dall'alto.

Ω (Omega) — lower bound
Ω(g(n)) = { f(n) : ∃ c > 0, ∃ n₀ > 0 : 0 ≤ c·g(n) ≤ f(n) ∀ n ≥ n₀ }

f(n) = Ω(g(n)) significa: f cresce almeno come g. f resta sopra c·g per tutti i n grandi.

Interpretazione: g è un lower bound (limite inferiore) per f.

Θ (Theta) — tight bound
Θ(g(n)) = { f(n) : ∃ c₁, c₂ > 0, ∃ n₀ > 0 : c₁·g(n) ≤ f(n) ≤ c₂·g(n) ∀ n ≥ n₀ }

f(n) = Θ(g(n)) significa: f è sandwichata tra due multipli costanti di g. Cresce esattamente come g.

Teorema fondamentale:

f(n) = Θ(g(n)) ⟺ f(n) = O(g(n)) ∧ f(n) = Ω(g(n))

Θ, O, Ω sono le relazioni asintotiche di uguaglianza (≈), maggiore-uguale (≥), minore-uguale (≤) tra funzioni.

Dimostrazione guidata: n² + 10n + 100 = Θ(n²)

  1. Upper bound (O): Per n ≥ 1: n² + 10n + 100 ≤ n² + 10n² + 100n² = 111n². Quindi f(n) ≤ 111·n² per n ≥ 1 → f = O(n²).
  2. Lower bound (Ω): Per n ≥ 1: n² + 10n + 100 ≥ n². Quindi f(n) ≥ 1·n² → f = Ω(n²).
  3. Conclusione: f = O(n²) ∧ f = Ω(n²) → f = Θ(n²). ∎

o (little-o) e ω (little-omega) — bound non stretti

O e Ω ammettono bound che potrebbero non essere asintoticamente stretti (tight). Per esempio n log n = O(n²) è vero, ma n log n ≠ Θ(n²) perché n log n cresce molto più lentamente di n².

o e ω — bound «stretti»
o(g) = «f cresce strictamente più lentamente di g» (non solo «al massimo come g»). ω(g) = il contrario. Esempio: n = o(n²) perché n/n² → 0, ma n² = O(n²) e anche Θ(n²) — il bound O qui è stretto.
o(g(n)) — upper bound stretto
o(g(n)) = { f(n) : ∀ c > 0, ∃ n₀ : 0 ≤ f(n) < c·g(n) ∀ n ≥ n₀ }

Nota: per ogni c > 0 (non solo qualcuno), f resta sotto c·g. Significa che f cresce strettamente più lentamente di g.

Esempio: n = o(n²) perché n/n² = 1/n → 0.

ω(g(n)) — lower bound stretto
ω(g(n)) = { f(n) : ∀ c > 0, ∃ n₀ : 0 ≤ c·g(n) < f(n) ∀ n ≥ n₀ }

f cresce strettamente più velocemente di g.

Esempio: n² = ω(n) perché n²/n = n → ∞.

Tight vs non-tight
  • n² − n + 10 = O(n²) → tight (anche Θ(n²))
  • n log n = O(n²) → non tight (n log n = o(n²))
  • 2n = Ω(n log n) → non tight
  • n + 4n log n = Ω(n log n) → tight

Caratterizzare funzioni sconosciute: π(n)

Sia π(n) il numero di numeri primi ≤ n. Non conosciamo la formula esatta, ma possiamo caratterizzarla asintoticamente:

  • π(n) = O(n) — bound banale (al massimo n numeri)
  • π(n) = Ω(1) — bound banale (almeno 1 primo per n ≥ 2)
  • π(n) = Θ(n / log n) — bound non banale e stretto
Teorema dei numeri primi
limn→∞ π(n)·ln(n) / n = 1
Questo giustifica π(n) = Θ(n/log n). Le notazioni asintotiche servono proprio a descrivere funzioni che non conosciamo in forma chiusa.

Metodo del limite
Per decidere se f = O(g), calcola L = limn→∞ f(n)/g(n):
  • L = 0 → f = O(g) ✓, f = o(g) ✓
  • L = c > 0 (finito) → f = Θ(g) ✓
  • L = ∞ → f = Ω(g) ✓, f ≠ O(g)

Esercizio 1 — Soluzione

Tabella costi (n ≥ 1):

  • Riga 1 (s=0): 1 volta, costo c₁
  • Riga 2 (for header): n volte, costo c₂
  • Riga 3 (s=s+i): n volte, costo c₃
  • Riga 4 (return): 1 volta, costo c₄
T(n) = c₁ + c₄ + n(c₂ + c₃) = n·C + C' = Θ(n)

L'algoritmo è Θ(n) nel worst-case. Nota: la somma 1+2+…+n = n(n+1)/2 è il valore di s, non il costo computazionale.

Esercizio 2 — Soluzione
  1. YES. 3n² + 5n ≤ 3n² + 5n² = 8n² per n≥1 (O). E ≥ 3n² (Ω). Quindi Θ(n²).
  2. YES. Stirling: log(n!) = Θ(n log n). Più semplicemente: log(n!) = Σ log i = Θ(n log n) per integrale o confronto.
  3. YES. n100/2ⁿ → 0, quindi n100 = o(2ⁿ) ⊂ O(2ⁿ).
  4. YES. 2n+1 = 2·2ⁿ. Per Ω: 2n+1 ≥ 2·2ⁿ. Per O: 2n+1 ≤ 2·2ⁿ. Quindi Θ(2ⁿ).
Esercizio 3 — Soluzione

Tre cicli annidati: i va da 1 a n−2, j da i+1 a n−1, k da j+1 a n.

Numero di triple (i,j,k): C(n,3) = n(n−1)(n−2)/6

T(n) = Θ(n³)

Nel worst-case ogni triple viene controllata → Θ(n³)

Esercizio 4 — Soluzione

Cerchiamo c, n₀ tali che 5n + 20 ≤ c·n per tutti n ≥ n₀.

Per n ≥ 20: 5n + 20 ≤ 5n + n = 6n (poiché 20 ≤ n).

Quindi: c = 6, n₀ = 20. Verifica: 5n + 20 ≤ 6n ⟺ 20 ≤ n. ✓

Alternativa più semplice: c = 25, n₀ = 1 perché 5n + 20 ≤ 25n per n ≥ 1.

Esercizio 5 — Soluzione

Ogni chiamata Pingala(n) genera due sottochiamate di dimensione quasi n−1 e n−2. L'albero di ricorsione ha almeno 2n/2 foglie (ramo che sceglie sempre la chiamata più grande).

Ogni foglia costa O(1). Quindi T(n) ≥ 2n/2·c = Ω(2n/2).

Questo spiega perché Pingala è esponenziale mentre Pingala-Inc è lineare: stesso problema, struttura algoritmica diversa.
