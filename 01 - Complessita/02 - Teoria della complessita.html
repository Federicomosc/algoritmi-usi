Teoria della Complessità
Classi P, NP e NP-Completezza

Appunti didattici completi basati sulle slide di Antonio Carzaniga (USI, 20 maggio 2026). Copertura: classi di complessità, riduzioni polinomiali, SAT, Vertex Cover, 2-CNF-SAT.

Classe P Classe NP Riduzioni NP-Complete SAT
In parole semplici — la mappa del capitolo
  • P — problemi che sappiamo risolvere velocemente (tempo polinomiale)
  • NP — problemi la cui risposta «sì» è facile da controllare se qualcuno ti dà una prova (certificato)
  • NP-completo — i problemi «più difficili» di NP: se ne risolvessi uno in P, risolveresti tutto NP → P = NP
  • Riduzione — trasformare un problema in un altro: se A si riduce a B e B è facile, allora A è facile; se A è difficile, allora B è almeno altrettanto difficile

01Tempo polinomiale

Definizione
Un algoritmo è polynomial-time se il suo tempo di esecuzione worst-case T(n), su un input di dimensione n bit, è O(nk) per qualche costante k.

Intuitivamente: polinomiale = "gestibile" per input grandi. Super-polinomiale = "impraticabile" per input moderatamente grandi.

AlgoritmoWorst-casePolinomiale?
Find (sequenziale)O(n)✓ k=1
Binary SearchO(log n)✓ k=0
Tree-MinimumO(n)✓
RB-InsertO(log n)✓
Insertion SortO(n²)✓ k=2
HeapsortO(n log n)✓ k=2
Edit DistanceO(n²)✓ k=2
Enumerare tutti i sottoinsiemiΘ(2ⁿ)✗

Polinomiale vs super-polinomiale

Regola pratica del corso

polinomiale ≡ buono    super-polinomiale ≡ cattivo

Struttura combinatoriaNumeroClasse
Tutte le coppie di n oggettiΘ(n²)polinomiale
Tutte le terneΘ(n³)polinomiale
Tutte le k-uple (k fisso)Θ(nk)polinomiale
Tutti i sottoinsiemiΘ(2ⁿ)super-polinomiale
Tutte le permutazioniΘ(n!)super-polinomiale
Tutti gli alberi su n vertici (Cayley)Θ(nn−2)super-polinomiale
Tutti i tour completi (TSP brute force)Θ(n!)super-polinomiale
Tutti i tagli (cut) di un grafoΘ(2ⁿ)super-polinomiale
Tutti gli archi di un grafoΘ(n²)polinomiale
Attenzione
O(n100) è tecnicamente polinomiale ma impraticabile. O(1.00001ⁿ) è super-polinomiale ma potrebbe essere gestibile per n piccolo. La distinzione polinomiale/super-polinomiale è una approssimazione teorica, non una legge fisica.

02Problemi, istanze e soluzioni

Definizione — Problema
Un problema Q è una relazione binaria tra un insieme I di istanze e un insieme S di soluzioni.
Q ⊆ I × S

Un problema concreto ha I = S = {0,1}* (tutte le stringhe binarie). Ogni istanza e soluzione reale viene codificata come stringa binaria con una codifica "sensata" (che non gonfia eccessivamente la dimensione).

Problemi decisionali

Definizione
Un problema decisionale ha S = {0, 1}. L'output è solo "sì" o "no".
Esempio — Test di primalità (decisionale)

Input: un intero n (codificato in binario). Output: 1 se n è primo, 0 altrimenti.

1 → 0   (non primo)
10 → 1   (primo)
11 → 1   (primo)
100 → 0
101 → 1
...

Decisione vs ottimizzazione

Esempio — Cammino minimo

Versione ottimizzazione:

  • Input: grafo G, vertice sorgente a, vertice destinazione z
  • Output: sequenza di vertici a, c, …, z (il cammino più corto)

Versione decisionale:

  • Input: grafo G, sorgente a, destinazione z, lunghezza massima L = 10
  • Output: 1 se esiste un cammino da a a z di lunghezza ≤ 10, 0 altrimenti
Perché ci concentriamo sui problemi decisionali
  • Un problema di ottimizzazione è almeno difficile quanto la sua versione decisionale: se risolvi l'ottimizzazione, rispondi subito alla decisione.
  • Non è molto più difficile: dalla versione decisionale si può spesso ricostruire la soluzione ottima con ricerca binaria (es. trovare la lunghezza minima chiedendo "esiste cammino di lunghezza ≤ L?" per diversi L).

03La classe di complessità P

Definizione
Un problema decisionale Q è polynomial-time solvable se esiste un algoritmo A che lo risolve in tempo polinomiale nel worst-case.
P = { Q decisionale : ∃ algoritmo A, A risolve Q in O(nk) }
Esempi di problemi in P
  • Cammino minimo (versione decisionale) — Dijkstra in O(n²) o O((V+E) log V)
  • Test di primalità — risultato di Agrawal, Kayal, Saxena (AKS, 2002): O(log12 n). Kayal e Saxena erano studenti di laurea triennale all'IIT Kanpur!
  • Parsing di un programma Java — algoritmi di parsing in tempo lineare o quasi-lineare
  • 2-CNF-SAT — vedremo che è in P tramite riduzione a reachability

04Verifica polinomiale

Per molti problemi difficili, trovare una soluzione è costoso, ma verificare una soluzione candidata è facile.

Analogia — sudoku
Risolvere un sudoku difficile può richiedere ore di tentativi. Ma se qualcuno ti consegna la griglia compilata, verificare che sia corretta (righe, colonne, box) richiede pochi secondi. NP modella proprio questa asimmetria: trovare vs controllare.
problema + istanza x ──?──► sì/no Se abbiamo un "certificato" y (prova della risposta "sì"): istanza x + certificato y ──► algoritmo di verifica A ──► valido / invalido in tempo polinomiale
Esempio — Vertex Cover (decisionale)

Input: grafo G = (V,E), intero K

Output: 1 se esiste un insieme S ⊆ V con |S| ≤ K tale che ogni arco (u,v) ∈ E ha u ∈ S o v ∈ S

Certificato: l'insieme S stesso (lista di ≤ K vertici)

Verifica: controlla che |S| ≤ K e che ogni arco sia coperto → O(|E|·|S|) = polinomiale

Non sappiamo se esista un algoritmo polinomiale per trovare S, ma se qualcuno ci dà S, possiamo verificarlo velocemente.

05La classe di complessità NP

Definizione — Polynomial-time verifiable
Un problema decisionale Q è polynomial-time verifiable se:
  1. Esiste un algoritmo di verifica A che gira in tempo polinomiale
  2. Per ogni istanza x con risposta "sì" (Q(x) = 1), esiste un certificato y di dimensione polinomiale |y| = O(|x|c)
  3. Tale che A(x, y) = 1 (il certificato è accettato)
NP = { Q decisionale : Q è polynomial-time verifiable }
NP ≠ "Non-Polynomial"!

NP sta per "Nondeterministic Polynomial" (tempo polinomiale su una macchina non deterministica). È la classe dei problemi la cui risposta "sì" è verificabile in tempo polinomiale.

Relazione fondamentale
P ⊆ NP

Se posso risolvere un problema in tempo polinomiale, posso anche verificarlo: il certificato è la traccia dell'esecuzione (o la soluzione trovata dall'algoritmo), e la verifica consiste nel rilanciare l'algoritmo.

La grande domanda aperta: P = NP?

Problema del millennio
P = NP ?

Se polynomial-time verifiable ⟹ polynomial-time solvable, allora P = NP.

Altrimenti esistono problemi verificabili in tempo polinomiale ma non risolvibili in tempo polinomiale → P ⊊ NP.

La maggior parte dei teorici crede che P ≠ NP: trovare una soluzione sarebbe intrinsecamente più difficile che verificarla. Ma nessuno ha dimostrato né P = NP né P ≠ NP.

06SAT — Satisfiability

Definizione — SAT

Input: una formula booleana su n variabili x₁, x₂, …, xₙ (con connettivi ∧, ∨, ¬)

Output: 1 se esiste un'assegnazione di verità che soddisfa la formula, 0 altrimenti

Esempi

Formula 1: ¬x ∧ (¬y ∨ ¬z) ∧ ¬z ∧ (x ∨ y)

Assegnazione: x=0, y=1, z=0 → tutte le clausole vere → SATISFIABLE → output 1

Formula 2: (x ∨ y ∨ z) ∧ (x ∨ ¬y) ∧ (y ∨ ¬z) ∧ (z ∨ ¬x) ∧ (¬x ∨ ¬y ∨ ¬z)

Nessuna assegnazione soddisfa tutte le clausole → UNSATISFIABLE → output 0

SAT ∈ NP?

SÌ. Certificato: un'assegnazione (n bit). Verifica: valuta la formula in O(n) per ogni clausola → tempo polinomiale.

SAT ∈ P?

Non lo sappiamo. Brute force su 2ⁿ assegnazioni è esponenziale. Nessun algoritmo polinomiale noto (e se P≠NP, non ne esiste).

07Vertex Cover (VC)

Definizione

Input: grafo G = (V, E), intero K

Output: 1 se esiste S ⊆ V con |S| ≤ K tale che ∀ (u,v) ∈ E: u ∈ S ∨ v ∈ S

Un vertex cover è un insieme di vertici che "tocca" ogni arco del grafo. La versione decisionale chiede se ne esiste uno di dimensione ≤ K.

VC ∈ NP?

SÌ. Certificato: l'insieme S (≤ K vertici, codifica polinomiale). Verifica: per ogni arco, controlla se un estremo è in S.

VC ∈ P?

Non lo sappiamo. Brute force: prova tutti i sottoinsiemi di ≤ K vertici → O(nK) o O(2ⁿ). Se K è grande, esponenziale.

08Riduzioni polinomiali

Vogliamo dimostrare che un problema Q′ è almeno difficile quanto un problema Q. Lo facciamo con una riduzione polinomiale.

Analogia — traduttore automatico
La riduzione A è come un traduttore veloce: trasforma ogni domanda in italiano (istanza di Q) in una domanda equivalente in francese (istanza di Q′). Se sai rispondere in francese velocemente, allora sai rispondere anche in italiano (componi traduzione + risposta). Se l'italiano è intrinsecamente difficile, anche il francese non può essere «troppo facile».
Definizione — Riduzione polinomiale Q → Q′
Esiste un algoritmo A in tempo polinomiale che:
  1. Trasforma ogni istanza q di Q in un'istanza q′ di Q′
  2. Tale che: Q(q) = 1 ⟺ Q′(q′) = 1 (stessa risposta sì/no)
Scriviamo: Q ≤p Q′ ("Q si riduce polinomialmente a Q′")
Schema di riduzione: istanza q di Q ──A (poly-time)──► istanza q′ di Q′ ──?──► soluzione Se Q′ è risolvibile in tempo polinomiale (Q′ ∈ P): istanza q di Q ──A──► q′ ──AQ′──► soluzione Composizione: A + AQ′ risolve Q in tempo polinomiale → Q ∈ P
Teorema — Riduzione e difficoltà
  • Se Q ≤p Q′ e Q′ ∈ P, allora Q ∈ P
  • Equivalently: se Q ∉ P (si crede), allora Q′ ∉ P
  • La riduzione trasferisce la difficoltà da Q a Q′

092-CNF-SAT ∈ P — Riduzione a reachability

2-CNF-SAT è una restrizione di SAT dove ogni clausola ha esattamente 2 letterali. Sorprendentemente, è in P (a differenza di SAT generale).

Definizione — 2-CNF-SAT

Input: formula f = C₁ ∧ C₂ ∧ … ∧ Cₖ in CNF, ogni Cᵢ = (a ∨ b) con letterali (variabile o negazione)

Output: 1 se f è soddisfacibile

Esempio: (x₁ ∨ ¬x₃) ∧ (¬x₂ ∨ x₃) ∧ (¬x₁ ∨ ¬x₃) ∧ (x₁ ∨ x₂)

Perché 2-CNF è facile ma SAT no?
Con 2 letterali per clausola, le implicazioni formano un grafo e il test «è soddisfacibile?» diventa «esiste un ciclo impossibile xᵢ ⇝ ¬xᵢ ⇝ xᵢ?» — risolvibile con DFS in tempo polinomiale. SAT generale non ha questa struttura semplice.

Passo 1 — Forma implicativa

Ogni clausola (a ∨ b) è equivalente a due implicazioni:

(a ∨ b) ≡ (¬a ⇒ b) ≡ (¬b ⇒ a)
Esempio di conversione

(x₁ ∨ ¬x₃) ∧ (¬x₂ ∨ x₃) diventa:

(¬x₁ ⇒ ¬x₃) ∧ (x₃ ⇒ x₁) ∧ (x₂ ⇒ x₃) ∧ (¬x₃ ⇒ ¬x₂)

Passo 2 — Grafo delle implicazioni

Costruiamo un grafo diretto G con 2n nodi: per ogni variabile xᵢ, nodi xᵢ e ¬xᵢ. Per ogni implicazione (a ⇒ b), aggiungiamo arco a → b.

Passo 3 — Criterio di insoddisfacibilità

Teorema
La formula 2-CNF è NON soddisfacibile se e solo se esiste una variabile xᵢ tale che nel grafo esiste un cammino xᵢ ⇝ ¬xᵢ e un cammino ¬xᵢ ⇝ xᵢ.

Intuizione: se xᵢ implica ¬xᵢ e ¬xᵢ implica xᵢ, allora xᵢ e ¬xᵢ devono avere lo stesso valore — impossibile.

Passo 4 — Algoritmo

  1. Converti la formula 2-CNF in forma implicativa
  2. Costruisci il grafo G (O(n + k) archi, k = numero clausole)
  3. Per ogni variabile xᵢ, esegui DFS/BFS da xᵢ: se raggiungi ¬xᵢ, e DFS da ¬xᵢ raggiunge xᵢ → UNSAT
  4. Se nessuna variabile viola il criterio → SAT
Complessità

Costruzione grafo: O(n + k). Per ogni variabile (n volte), DFS: O(n + k). Totale: O(n·(n+k)) = O(n²) → polinomiale. Quindi 2-CNF-SAT ∈ P.

Riduzione formale: istanza 2-CNF-SAT ──poly-time──► istanza "reachability in grafo" ──DFS──► soluzione 2-CNF-SAT ≤p Reachability, e Reachability ∈ P → 2-CNF-SAT ∈ P

10NP-completeness e NP-hardness

NP-hard vs NP-complete — differenza pratica
  • NP-hard — «almeno difficile quanto tutto NP» (può non essere in NP: es. problemi di ottimizzazione)
  • NP-complete — NP-hard e in NP: è verificabile in tempo polinomiale e è tra i più difficili
SAT e Vertex Cover sono NP-complete. Se trovassi un algoritmo polinomiale per uno di loro, avresti risolto il problema del millennio P = NP.
Definizioni formali
  • NP-hard: Q′ è NP-hard se ogni problema Q ∈ NP è polynomial-time riducibile a Q′ (Q ≤p Q′ per tutti Q ∈ NP)
  • NP-complete: Q′ è NP-complete se Q′ ∈ NP e Q′ è NP-hard
Proprietà chiave
  • Se Q′ è NP-hard e Q′ ≤p Q′′, allora Q′′ è NP-hard (per transitività)
  • Se Q′ è NP-hard e Q′ ∈ P, allora P = NP (quasi tutti credono che questo non accada)
  • Se un problema è NP-complete, non dovresti sentirti in colpa per non trovare un algoritmo efficiente!

Il primo problema NP-completo: SAT

Teorema di Cook-Levin (1971): Qualsiasi Q ∈ NP ──poly-time reduction──► SAT SAT è NP-hard. Poiché SAT ∈ NP → SAT è NP-complete. Catena di riduzioni successive: SAT ──≤p──► 3-SAT ──≤p──► Vertex Cover ──≤p──► ...
Esempio — Vertex Cover è NP-complete
  1. VC ∈ NP (certificato = insieme S, verifica polinomiale) ✓
  2. SAT ≤p VC (riduzione nota, non la vediamo in dettaglio) ✓
  3. SAT è NP-hard ✓
  4. Per transitività: VC è NP-hard. Con VC ∈ NP → VC è NP-complete

Esercizio 5 — P vs NP

Rispondi VERO o FALSO con spiegazione:

  1. Se P = NP, allora ogni problema in NP ha un algoritmo O(n100)
  2. Se un problema è NP-hard, allora è necessariamente NP-complete
  3. Se Q₁ ≤p Q₂ e Q₂ ≤p Q₁, allora Q₁ e Q₂ hanno la stessa difficoltà
  4. Se troviamo un algoritmo polinomiale per SAT, allora P = NP

E2Soluzioni dettagliate

Esercizio 1 — Soluzione
  1. Super-polinomiale — n! permutazioni
  2. Polinomiale — O(n log n) ⊆ O(n²)
  3. Super-polinomiale — 2ⁿ sottoinsiemi
  4. Polinomiale — O(n²) con programmazione dinamica
Esercizio 2 — Soluzione
  1. Certificato: una sequenza di vertici v₁, v₂, …, vₙ che forma un ciclo hamiltoniano (ogni vertice appare una volta, archi consecutivi esistono, vₙ collegato a v₁)
  2. Verifica: (a) controlla che ci siano n vertici distinti, (b) per ogni coppia consecutiva (vᵢ, vᵢ₊₁) verifica che l'arco esista, (c) verifica arco (vₙ, v₁). Tutto in O(n + |E|) = polinomiale
  3. NP: esiste certificato di dimensione O(n log n) bit e verifica in tempo polinomiale
Esercizio 3 — Soluzione

Sì, Clique è NP-complete.

Riduzione IS ≤p Clique: dato G = (V,E) e K, costruisci il grafo complemento G' = (V, E') dove (u,v) ∈ E' sse (u,v) ∉ E.

Un insieme S è independent set in G ⟺ S è clique in G'. Infatti: in G nessuna coppia in S è adiacente ⟺ in G' ogni coppia in S è adiacente.

La costruzione di G' richiede O(n²) → riduzione polinomiale. IS è NP-complete → Clique è NP-hard. Clique ∈ NP (certificato = insieme di vertici) → Clique è NP-complete.

Esercizio 4 — Soluzione

Implicazioni (archi del grafo):

  • (x∨y) → ¬x→y, ¬y→x
  • (¬x∨y) → x→y, ¬y→¬x
  • (¬y∨z) → y→z, ¬z→¬y
  • (¬z∨¬x) → z→¬x, x→¬z

Verifica x ⇝ ¬x: x → y → z → ¬x. Cammino trovato.

Verifica ¬x ⇝ x: da ¬x si raggiunge solo y (¬x→y), poi z (y→z), poi ¬x (z→¬x). Non si raggiunge mai x. Nessun cammino ¬x ⇝ x.

Il criterio di insoddisfacibilità richiede entrambi i cammini per la stessa variabile. Qui manca ¬x ⇝ x, quindi il criterio non scatta.

Assegnazione soddisfacente: x=0, y=1, z=1

  • (x∨y) = (0∨1) = 1 ✓
  • (¬x∨y) = (1∨1) = 1 ✓
  • (¬y∨z) = (0∨1) = 1 ✓
  • (¬z∨¬x) = (0∨1) = 1 ✓

Conclusione: la formula è SATISFIABLE.

Esercizio 5 — Soluzione
  1. VERO. P = NP significa che ogni problema NP è risolvibile in tempo O(nk) per qualche k. In particolare O(n100) per k=100.
  2. FALSO. NP-hard non richiede che il problema sia in NP. Un problema può essere NP-hard senza essere verificabile in tempo polinomiale (es. problemi di ottimizzazione o problemi con output non binario, se definiti fuori dal framework decisionale standard).
  3. VERO (con cautela). Riduzioni bidirezionali implicano stessa classe di difficoltà. Se Q₁ ≤p Q₂ e Q₂ ≤p Q₁, allora Q₁ e Q₂ sono "equivalenti" per riduzioni polinomiali.
  4. VERO. SAT è NP-complete. Se SAT ∈ P, allora ogni problema in NP si riduce a un problema in P, quindi è in P. Quindi P = NP.
