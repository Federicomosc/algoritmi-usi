01Il Modello RAM

Cos'è

Il modello RAM (Random-Access Machine) è il modello standard per analizzare la complessità. Assume che ogni operazione "elementare" costi esattamente 1 passo, indipendentemente dai valori coinvolti.

Definizione
Sono passi elementari: assegnamenti (x = 5), operazioni aritmetiche (a + b), confronti (a < b), branch (if/while), chiamate a funzione. Ogni passo conta come 1 unità di costo costante.

Come si calcola T(n)

Si costruisce una tabella costo × volte: per ogni riga di codice si scrive il costo (costante ci) e quante volte viene eseguita in funzione di n.

Esempio — PINGALA-INC(n)
PINGALA-INC(n)             costo   volte (n > 2)
1  if n ≤ 2               c₁      1
2    return n              c₂      0
3  pprev = 1               c₃      1
4  prev  = 2               c₄      1
5  for i = 3 to n         c₅      n−1   ← header del for
6    P = prev + pprev      c₆      n−2
7    pprev = prev          c₇      n−2
8    prev  = P             c₈      n−2
9  return P               c₉      1

T(n) = c₁ + c₃ + c₄ + c₉ + (n−1)c₅ + (n−2)(c₆+c₇+c₈)
     = n·C₁ + C₂   →  T(n) = Θ(n)
Trucco esame
Non serve calcolare i ci esatti. Basta contare quante volte ogni loop viene eseguito, sommare i contributi, e tenere solo il termine dominante. Tutti i coefficienti costanti spariscono nella notazione Θ.

02Notazione Asintotica

Le tre notazioni principali

Big-O — Upper bound
f(n) = O(g(n))

significa che esistono costanti c > 0 e n₀ tali che:

f(n) ≤ c · g(n)   per ogni n ≥ n₀

g domina f "da sopra" — f cresce al massimo come g. È come dire f ≤ g asintoticamente.

Ω (Omega) — Lower bound
f(n) = Ω(g(n))

significa che esistono costanti c > 0 e n₀ tali che:

f(n) ≥ c · g(n)   per ogni n ≥ n₀

f cresce almeno come g. È come dire f ≥ g asintoticamente.

Θ (Theta) — Tight bound — IL PIÙ IMPORTANTE
f(n) = Θ(g(n))

significa che esistono costanti c₁, c₂ > 0 e n₀ tali che:

c₁ · g(n) ≤ f(n) ≤ c₂ · g(n)   per ogni n ≥ n₀

f cresce esattamente come g. È come dire f = g asintoticamente. È il più preciso.

Teorema fondamentale: f = Θ(g)   ⟺   f = O(g)   ∧   f = Ω(g)

Come semplificare T(n) in Θ

  1. Espandi T(n) per intero (somma di tutti i contributi dei loop)
  2. Identifica il termine che cresce più velocemente (ignora gli altri)
  3. Elimina i coefficienti moltiplicativi costanti
  4. Scrivi Θ(termine dominante)

Gerarchia delle classi di complessità
O(1)  ≪  O(log n)  ≪  O(√n)  ≪  O(n)  ≪  O(n log n)  ≪  O(n1.5)  ≪  O(n²)  ≪  O(2n)  ≪  O(3n)

Ogni classe domina (cresce più velocemente di) tutte quelle a sinistra. Conseguenza: nel Θ di una somma, vince sempre il termine più a destra in questa scala.

03Sorting O(n²)

Insertion Sort

Idea: mantieni la parte sinistra A[0..i-1] sempre ordinata. Ad ogni passo i, inserisci A[i] nella posizione giusta scorrendo a ritroso e facendo swap.

INSERTION-SORT(A)
for i = 1 to A.length − 1
    j = i
    while j > 0 and A[j−1] > A[j]
        swap(A[j], A[j−1])
        j = j − 1
CasoInputCiclo internoT(n)
Miglioregià ordinatowhile non esegue maiΘ(n)
Mediocasuale~(j-1)/2 iterazioniΘ(n²)
Peggioreordinato inversamentej-1 iterazioniΘ(n²)

Invariante: prima di ogni iterazione i, A[0..i-1] è ordinato e contiene gli stessi elementi originali. In-place O(1) spazio. Stabile.

Selection Sort

Idea: ad ogni passo i, trova il minimo di A[i..n-1] e portalo in A[i] con un unico swap.

SELECTION-SORT(A)
for i = 0 to A.length − 2
    smallest = i
    for j = i+1 to A.length − 1
        if A[j] < A[smallest]
            smallest = j
    swap(A[i], A[smallest])

Il ciclo interno esegue sempre (n−1−i) iterazioni, indipendentemente dall'input → T(n) = Θ(n²) in tutti i casi. Vantaggio: al massimo n−1 swap totali (utile se lo swap è costoso). Non stabile.

Bubble Sort

Idea: confronta coppie adiacenti, sposta i grandi verso destra. Ottimizzazione con flag: se non ci sono swap in un passaggio, l'array è già ordinato.

BUBBLE-SORT(A)
for i = 0 to A.length − 2
    swapped = false
    for j = 0 to A.length − 2 − i
        if A[j] > A[j+1]
            swap(A[j], A[j+1])
            swapped = true
    if not swapped: break   ← uscita anticipata

Con la flag: Θ(n) se già ordinato, Θ(n²) altrimenti. Stabile, in-place.

04Divide & Conquer

Schema generale: DIVIDE il problema in k sotto-problemi più piccoli → CONQUER risolvi ricorsivamente ogni sotto-problema → COMBINE unisci le soluzioni. La ricorrenza è:

T(n) = Tdivide + k · T(n/k) + Tcombine

Binary Search — O(log n)

Cerca un elemento in un array ordinato dimezzando lo spazio di ricerca ad ogni passo.

BINARY-SEARCH(A, key)
first = 0,  last = A.length − 1
while first ≤ last
    middle = (first + last + 1) / 2   ← divisione intera, arrot. superiore
    if A[middle] == key:  return true
    if first == last:     return false
    if A[middle] > key:   last  = middle − 1
    else:                 first = middle + 1
return false

Ricorrenza: T(n) = T(n/2) + O(1) → O(log n). Prerequisito assoluto: array ordinato.

MergeSort — Θ(n log n)

Divide a metà (O(1)), ordina ricorsivamente le due metà, le fonde con MERGE (Θ(n)).

MERGESORT(A)
if A.length ≤ 1: return A
mid = A.length / 2
L = MERGESORT(A[0..mid−1])
R = MERGESORT(A[mid..n−1])
return MERGE(L, R)

MERGE(L, R)             ← Θ(n) dove n = |L| + |R|
result = [],  i = 0,  j = 0
while i < L.length and j < R.length
    if L[i] ≤ R[j]: append L[i]; i++
    else:            append R[j]; j++
return result + L[i:] + R[j:]

Ricorrenza: T(n) = 2T(n/2) + Θ(n) → Θ(n log n) in tutti i casi. Stabile, ma non in-place (usa O(n) spazio).

QuickSort — Θ(n log n) medio / Θ(n²) peggiore

Sceglie un pivot, partiziona l'array attorno ad esso (elementi ≤ pivot a sinistra, > a destra), poi ordina ricorsivamente le due parti. In-place.

PARTITION(A, begin, end)       ← pivot = A[end], Θ(n)
q = begin,  v = A[end]
for i = begin to end
    if A[i] ≤ v
        swap(A[i], A[q]);  q++
return q − 1    ← posizione finale del pivot

QUICKSORT(A, begin, end)
if begin < end
    q = PARTITION(A, begin, end)
    QUICKSORT(A, begin, q−1)
    QUICKSORT(A, q+1, end)
CasoQuandoRicorrenzaT(n)
Migliorepivot sempre al centroT(n) = 2T(n/2) + Θ(n)Θ(n log n)
Mediopivot casualeanalisi probabilisticaΘ(n log n)
Peggiorearray già ordinato (pivot=min/max)T(n) = T(n−1) + Θ(n)Θ(n²)

Scambia A[random(begin,end)] con A[end] prima di chiamare PARTITION. Il caso peggiore diventa di probabilità 1/n! — praticamente impossibile. Complessità attesa: Θ(n log n).

Teorema Master

Per ricorrenze della forma T(n) = a·T(n/b) + f(n) con a≥1, b>1:

  • Caso 3: se f(n) = Ω(nc) con c > ccrit → T(n) = Θ(f(n))

05Binary Max-Heap & HeapSort

Struttura

Un Binary Max-Heap è un albero binario quasi-completo, memorizzato in un array (indice 0-based). La proprietà heap: ogni nodo è ≥ dei suoi figli. Conseguenza: A[0] è sempre il massimo.

Navigazione in O(1):

PARENT(i) = (i−1) / 2     ← divisione intera
LEFT(i)   = 2·i + 1
RIGHT(i)  = 2·i + 2
Esempio visivo — Heap [16, 14, 10, 8, 7, 9, 3]
                  16    ← A[0] = massimo
                /    \
             14      10
            /  \    /  \
          8    7  9    3

Array: [16, 14, 10, 8, 7, 9, 3]
        0   1   2   3  4  5  6

Operazioni fondamentali

MAX-HEAPIFY — O(log n) — ripristina la proprietà

Assume che i sottoalberi di i siano già heap validi, ma i potrebbe violare la proprietà. "Fa scendere" i verso il basso.

MAX-HEAPIFY(A, i)
largest = i
l = LEFT(i),  r = RIGHT(i)
if l < heap_size and A[l] > A[largest]:  largest = l
if r < heap_size and A[r] > A[largest]:  largest = r
if largest ≠ i
    swap(A[i], A[largest])
    MAX-HEAPIFY(A, largest)    ← ricorsione verso il basso

BUILD-MAX-HEAP — O(n) — costruisce heap da array

Chiama MAX-HEAPIFY da metà array verso l'inizio (le foglie sono già heap banali).

BUILD-MAX-HEAP(A)
heap_size = A.length
for i = A.length/2 − 1 downto 0
    MAX-HEAPIFY(A, i)
Perché O(n) e non O(n log n)?
Intuitivamente: i nodi più in basso fanno pochissimo lavoro (le foglie fanno 0 heapify), quelli più in alto fanno O(log n). La somma pesata dà O(n). Questo è un risultato non banale ma importante.

HEAP-EXTRACT-MAX — O(log n) — estrae il massimo

HEAP-EXTRACT-MAX(A)
max = A[0]                     ← salva il massimo (radice)
A[0] = A[heap_size − 1]        ← porta l'ultimo elemento in cima
heap_size = heap_size − 1
MAX-HEAPIFY(A, 0)              ← ripristina la proprietà heap
return max

HEAP-INSERT — O(log n) — inserisce un elemento

HEAP-INSERT(A, key)
heap_size = heap_size + 1
A[heap_size − 1] = key                ← inserisci in fondo
i = heap_size − 1
while i > 0 and A[PARENT(i)] < A[i]  ← "fai salire" verso radice
    swap(A[i], A[PARENT(i)])
    i = PARENT(i)

HeapSort — Θ(n log n) sempre

HEAPSORT(A)
BUILD-MAX-HEAP(A)            ← fase 1: O(n)
for i = A.length−1 downto 1
    swap(A[0], A[i])         ← porta il max in fondo
    heap_size = heap_size − 1
    MAX-HEAPIFY(A, 0)        ← ripristina heap  O(log n) × n volte

In-place, O(1) spazio extra. Non stabile. T(n) = Θ(n log n) in tutti i casi.

06Binary Search Tree (BST)

Proprietà BST: per ogni nodo x, tutti i nodi nel sottoalbero sinistro hanno chiave < x.key, tutti quelli nel sottoalbero destro hanno chiave ≥ x.key (oppure >, dipende dalla definizione — a USI di solito stretto su entrambi i lati per chiavi distinte).

Struttura di un nodo: x.key, x.left, x.right, x.parent (può essere nil).

Operazioni base — O(h) dove h = altezza

BST-SEARCH

BST-SEARCH(t, k)
if t == nil or t.key == k:  return t
if k < t.key:  return BST-SEARCH(t.left,  k)
else:          return BST-SEARCH(t.right, k)

BST-INSERT

BST-INSERT(t, k)
if t == nil:  return new node(k)
if k < t.key:  t.left  = BST-INSERT(t.left,  k)
else:          t.right = BST-INSERT(t.right, k)
return t

BST-MIN e BST-MAX

BST-MIN(t)                  BST-MAX(t)
while t.left ≠ nil          while t.right ≠ nil
    t = t.left                  t = t.right
return t                    return t

In-order traversal (visita simmetrica) — produce output ORDINATO

INORDER(t)
if t ≠ nil
    INORDER(t.left)
    print(t.key)       ← visita il nodo
    INORDER(t.right)

BST-DELETE — il più complesso

Tre casi:

  • Nodo foglia: rimuovi direttamente
  • Un solo figlio: collega il figlio al parent
  • Due figli: sostituisci con il successore in-order (= minimo del sottoalbero destro), poi elimina il successore
Complessità BST
Tutte le operazioni sono O(h). Se il BST è bilanciato: h = O(log n) quindi O(log n). Se è degenere (es. inserisci 1,2,3,...,n in ordine): h = n−1 quindi O(n).

07Liste Concatenate

Singly Linked List

Ogni nodo ha x.value e x.next (nil se ultimo). La lista è referenziata dalla testa (head).

// Inserisci in testa — O(1)
INSERT-HEAD(L, x)
    x.next = L;  return x

// Cerca elemento — O(n)
SEARCH(L, k)
    curr = L
    while curr ≠ nil
        if curr.value == k: return curr
        curr = curr.next
    return nil

// Lunghezza — O(n)
LENGTH(L)
    n = 0;  curr = L
    while curr ≠ nil:  n++;  curr = curr.next
    return n

Doubly Linked List con Sentinella

La sentinella è un nodo speciale (nil) che funge da "dummy" — non contiene dati reali. Ogni nodo ha x.value, x.next, x.prev. La lista è referenziata dalla sentinella s: s.next è il primo nodo, s.prev è l'ultimo.

Vantaggi della sentinella
Elimina i casi speciali: lista vuota (s.next = s.prev = s), inserimento e cancellazione non richiedono mai di controllare se si è all'inizio o alla fine. Il codice diventa molto più pulito. 
// Inserisci dopo nodo p — O(1)
INSERT-AFTER(p, x)
    x.next = p.next;  x.prev = p
    p.next.prev = x;  p.next = x

// Rimuovi nodo x — O(1) dato il nodo
REMOVE(x)
    x.prev.next = x.next
    x.next.prev = x.prev

Split di una lista (midterm ricorrente)

// Singly: trova il punto medio con due puntatori
SPLIT-SINGLY(L)
    slow = L;  fast = L
    while fast.next ≠ nil and fast.next.next ≠ nil
        slow = slow.next
        fast = fast.next.next
    // slow punta alla fine della prima metà
    R = slow.next
    slow.next = nil
    return (L, R)

Complessità: O(n). La tecnica del fast/slow pointer (puntatore veloce e lento) è fondamentale per problemi sulle liste.

08Come Analizzare un Algoritmo Dato

Il tipo di esercizio più frequente: ti danno uno pseudocodice e chiedono "cosa fa?" + "qual è la complessità?". Ecco il metodo sistematico.

Step 1 — Traccia con un esempio piccolo

Prima di qualsiasi ragionamento teorico, esegui l'algoritmo mentalmente su un array di 4–5 elementi. Questo ti dà immediatamente un'intuizione di cosa fa.

Step 2 — Identifica la struttura dei loop

  1. Conta i loop annidati. Ogni livello di annidamento di solito moltiplica la complessità.
  2. Per ogni loop, determina quante volte esegue in funzione di n (o altra variabile).
  3. Fai la somma delle iterazioni totali (prodotto per loop annidati).
  4. Semplifica con Θ, tenendo solo il termine dominante.
Pattern tipici e la loro complessità
// Ciclo singolo semplice → Θ(n)
for i = 1 to n:  ...

// Due cicli annidati indipendenti → Θ(n²)
for i = 1 to n:
    for j = 1 to n:  ...

// Due cicli annidati con j che parte da i → Θ(n²)   (somma = n(n-1)/2)
for i = 1 to n:
    for j = i+1 to n:  ...

// Ciclo esterno n, ciclo interno dipende da i → analizza caso per caso
for i = 1 to n:
    while j < i:  ...         → Θ(n²) (somma 1+2+...+n)

// Ciclo che dimezza → Θ(log n)
while n > 1:  n = n / 2

// Ciclo esterno n, ciclo interno log n → Θ(n log n)
for i = 1 to n:
    j = n
    while j > 1:  j = j / 2

// Tre cicli annidati n×n×n → Θ(n³)
for i=1 to n:
    for j=1 to n:
        for k=1 to n:  ...

Step 3 — Spiega cosa fa (in italiano, non parafrasare il codice)

Errore comune da evitare
Non scrivere "scorre l'array con i, poi con j controlla ogni elemento...". Questo è parafrasare il codice. Il professore vuole la semantica ad alto livello: "questo algoritmo conta le coppie di elementi che differiscono di esattamente 1" oppure "restituisce il k-esimo elemento distinto dell'array".

Esempio completo — m24 Exercise 300

Algo-X(A)
1  n = A.length
2  x = 0
3  for i = 1 to n          ← n iterazioni
4      for j = 1 to n      ← n iterazioni
5          for k = 1 to n  ← n iterazioni
6              if A[k]−A[j]==1 and A[j]−A[i]==1
7                  x = x + 1
8  return x

Semantica: conta il numero di triple ordinate (i, j, k) di indici tali che A[i], A[j], A[k] formano una sequenza di tre valori consecutivi (ogni valore è esattamente 1 più del precedente). In altre parole, conta le triple con A[i]+1 = A[j] e A[j]+1 = A[k].

Complessità: tre cicli annidati su n → Θ(n³).

09Come Migliorare un Algoritmo

La domanda classica: dato Algo-X lento, scrivi Better-Algo-X con complessità migliore. Questo è il cuore del corso. Ci sono 5 tecniche principali.

Tecnica 1 — Ordina prima, poi usa binary search o two-pointer

Se hai cicli annidati per cercare elementi, puoi spesso:

  1. Ordinare l'array in O(n log n)
  2. Per ogni elemento, usare binary search O(log n) invece di scan lineare O(n)
  3. Totale: O(n log n) invece di O(n²)
Esempio — Algo-Y: conta coppie con A[i]+A[j]=s (f24 Ex.306)
// Lento: O(n²)
for i = 1 to n:
    for j = i+1 to n:
        if A[i] + A[j] == s:  x++

// Veloce: Sort + two-pointer = O(n log n)
Sort(A)
left = 0,  right = n−1
while left < right
    sum = A[left] + A[right]
    if   sum == s:  x++;  left++;  right--
    elif sum <  s:  left++
    else:           right--

Tecnica 2 — Usa una hash table / dizionario

Se la ricerca di un elemento in un insieme è il collo di bottiglia (O(n) con scan), sostituiscila con una hash table che fa insert e lookup in O(1) atteso.

  1. Prima passata: inserisci tutti gli elementi nell'hash table in O(n)
  2. Seconda passata: per ogni elemento, fai il lookup in O(1)
  3. Totale: O(n) invece di O(n²)
Esempio — conta le triple con A[k]−A[j]=A[j]−A[i]=1 (m24 Ex.300)
// Hash table conta le occorrenze di ogni valore
count = HashTable()
for v in A:  count[v]++        // O(n)

x = 0
for j = 1 to n:                 // O(n)
    // quante volte c'è A[j]−1 (il valore precedente)?
    prev = count.get(A[j] − 1, 0)
    // quante volte c'è A[j]+1 (il valore successivo)?
    nxt  = count.get(A[j] + 1, 0)
    x = x + prev * nxt           // ogni (i,j,k) con valori giusti
return x                         // O(n) totale!

Tecnica 3 — Sliding Window / Finestra Scorrevole

Utile per problemi su sottosequenze contigue. Invece di ricalcolare la somma/conteggio da zero per ogni finestra, tieni traccia del risultato corrente e aggiornalo incrementalmente.

Schema sliding window
left = 0,  stato = stato_iniziale
for right = 0 to n−1
    aggiungi A[right] allo stato       ← espandi finestra a destra
    while condizione_violata:
        rimuovi A[left] dallo stato    ← restringe da sinistra
        left++
    aggiorna il risultato con lo stato corrente

Tecnica 4 — Divide & Conquer / MergeSort-based

Problemi che hanno struttura ricorsiva possono spesso essere risolti con D&C. La chiave è riconoscere quando il problema si divide naturalmente in due metà.

Tecnica 5 — Preprocessing + struttura dati ausiliaria

Costruisci una struttura dati (prefix sums, sorted copy, heap, BST) in O(n) o O(n log n) che poi permette di rispondere a ogni query in O(1) o O(log n).

Prefix sums — calcola somme di range in O(1)
// Preprocessing O(n): costruisce l'array delle somme prefisse
P[0] = 0
for i = 1 to n:  P[i] = P[i−1] + A[i]

// Query O(1): somma di A[l..r]
SUM(l, r) = P[r] − P[l−1]

10Pattern Classici dell'Esame

Pattern A — "Spiega e migliora un algoritmo"

Struttura tipica: Algo-X fa qualcosa in O(n²) o O(n³). Scrivi Better-Algo-X con O(n log n) o O(n).

Checklist da seguire:

  1. Traccia con esempio piccolo → capisci la semantica
  2. Conta le iterazioni → calcola T(n) esatto in Θ
  3. Identifica il collo di bottiglia (il loop più costoso)
  4. Scegli la tecnica di ottimizzazione appropriata
  5. Riscrivi il codice e verifica che faccia la stessa cosa
  6. Analizza la nuova complessità e confronta

Pattern B — "Implementa un'operazione su struttura dati"

Ti chiedono es. Max-Heap-Delete, BST-Partition, Split-Linked-List. Come procedere:

  1. Ragiona sull'invariante della struttura dati (cosa deve essere vero prima e dopo)
  2. Pensa ai casi edge: lista vuota, nodo foglia, un solo figlio...
  3. Scrivi lo pseudocodice passo per passo
  4. Verifica con un esempio concreto disegnato a mano
  5. Analizza la complessità e giustificala

Pattern C — "Progetta un algoritmo da zero"

Ti danno un problema nuovo (es. "scrivi Mountain-Sort(A)"). Framework:

  1. Comprendi esattamente l'input e l'output desiderato
  2. Cerca una proprietà strutturale del problema (simmetria, ordinamento parziale, divisibilità...)
  3. Scegli la strategia: greedy, D&C, sorting+scan, DP...
  4. Dimostra (informalmente) la correttezza
  5. Analizza la complessità

Pattern D — Esercizi su Liste Concatenate

Ricorrenti nei midterm recenti. Punti chiave:

  • Usa sempre la tecnica del doppio puntatore (slow/fast) per trovare il punto medio
  • Per manipolazioni in-place, fai attenzione all'ordine in cui aggiorni i puntatori
  • Prima aggiorna il nodo che perderesti (quello che non puoi più raggiungere)
  • Testa mentalmente con lista vuota, lista di 1 elemento, lista di 2 elementi

11Template da Memorizzare per l'Esame

Max-Heap-Change-Value — O(log n)

Cambia H[i] a x e ripristina la proprietà heap.

MAX-HEAP-CHANGE-VALUE(H, i, x)
H[i] = x
// Caso 1: il nuovo valore è più grande → potrebbe violare verso l'alto
while i > 0 and H[PARENT(i)] < H[i]
    swap(H[i], H[PARENT(i)])
    i = PARENT(i)
// Caso 2: il nuovo valore è più piccolo → potrebbe violare verso il basso
MAX-HEAPIFY(H, i)

Max-Heap-Delete — O(log n)

MAX-HEAP-DELETE(H, i)
H[i] = H[H.heap-size]          ← sostituisci con l'ultimo
H.heap-size = H.heap-size − 1
MAX-HEAP-CHANGE-VALUE(H, i, H[i])  ← ripristina (su o giù)

BST-Lower-Bound — O(h)

Restituisce il nodo con il valore minimo ≥ x.

BST-LOWER-BOUND(t, x)
result = nil
while t ≠ nil
    if t.key >= x
        result = t          ← candidato: t.key ≥ x, potrebbe esserci di meglio a sx
        t = t.left
    else
        t = t.right         ← t.key < x: tutto il sottoalbero sx è troppo piccolo
return result

In-order BST come array — O(n)

BST-TO-ARRAY(t, arr, idx)
if t == nil: return idx
idx = BST-TO-ARRAY(t.left, arr, idx)
arr[idx++] = t.key
idx = BST-TO-ARRAY(t.right, arr, idx)
return idx

Merge Sort su lista concatenata — O(n log n)

LIST-SORT(L)
if L == nil or L.next == nil: return L
(L1, L2) = SPLIT-SINGLY(L)     ← divide a metà
L1 = LIST-SORT(L1)
L2 = LIST-SORT(L2)
return MERGE-LISTS(L1, L2)      ← fonde le due metà ordinate

MERGE-LISTS(L1, L2)
if L1 == nil: return L2
if L2 == nil: return L1
if L1.value ≤ L2.value
    L1.next = MERGE-LISTS(L1.next, L2);  return L1
else
    L2.next = MERGE-LISTS(L1, L2.next);  return L2

Errori tipici da non fare all'esame
  • Confondere O con Θ: se sai il bound esatto, usa sempre Θ. O è solo "al massimo".
  • Dire "la complessità è O(n²)" quando è Θ(n²) — è meno preciso del necessario.
  • Non considerare il caso base nella ricorsione.
  • Dimenticare che Binary Search richiede array ordinato.
  • Confondere BUILD-MAX-HEAP O(n) con "n volte HEAP-INSERT" O(n log n) — non sono equivalenti.
  • In QuickSort, il caso peggiore è array già ordinato (non inverso!) con pivot = A[end].
  • Non verificare i casi edge (lista vuota, array di 1 elemento, duplicati) nelle implementazioni.
Consiglio finale — Come gestiré il tempo all'esame
  • Leggi tutti gli esercizi prima di iniziare. Inizia da quello che conosci meglio.
  • Traccia sempre con un esempio piccolo (3–5 elementi) — risparmia tempo, evita errori.
  • Per la complessità: scrivi prima la formula T(n) per intero, poi semplifica. Mostra il ragionamento.
  • Se non trovi la soluzione ottimale, scrivi quella subottimale con la sua complessità — vale comunque punti parziali.
  • Alle domande "spiega cosa fa": una frase chiara e precisa vale più di tre righe vaghe.
