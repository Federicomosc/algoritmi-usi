Algoritmi «dividi e conquista»

Appunti completi dal PDF «Divide-and-Conquer Algorithms» (4 marzo 2026). Unione di insiemi, ricerca binaria, merge, MergeSort, Karatsuba e selezione del k-esimo elemento.

Divide & Conquer O(n log n) MergeSort
In parole semplici — cosa impari qui
La tecnica divide & conquer spezza un problema grande in pezzi più piccoli, li risolve ricorsivamente e combina i risultati. Da qui nascono Binary Search (O(log n)), MergeSort (O(n log n)), Karatsuba (moltiplicazione più veloce) e la ricerca del k-esimo elemento senza ordinare tutto l'array.

§1 La strategia Divide and Conquer

La tecnica Divide and Conquer (D&C, «dividi e conquista») risolve un problema ricorsivamente seguendo tre fasi distinte. È alla base di algoritmi fondamentali come MergeSort, QuickSort, ricerca binaria e Karatsuba.

✂
Divide

Scomponi il problema in sottoproblemi più piccoli dello stesso tipo, tipicamente di dimensione n/b per qualche b > 1.

⚡
Conquer

Risolvi ricorsivamente i sottoproblemi. Il caso base è quando la dimensione è sufficientemente piccola da risolvere direttamente in tempo costante.

🔗
Combine

Combina le soluzioni dei sottoproblemi per ottenere la soluzione del problema originale. Il costo di combinazione è spesso critico.

Ricorrenza generale D&C

Se dividiamo in a sottoproblemi di dimensione n/b ciascuno, e la fase di combinazione costa f(n):

T(n) = a · T(n/b) + f(n)

Il Master Theorem (visto nel corso) permette di risolvere molte ricorrenze di questo tipo senza espandere l'albero di ricorsione.

In breve

D&C = dividi in sottoproblemi indipendenti → risolvi ricorsivamente → combina. La complessità dipende da quanti sottoproblemi (a), quanto sono piccoli (b) e quanto costa combinare (f(n)).

Esempi di ricorrenze D&C

AlgoritmoRicorrenzaSoluzione
Binary SearchT(n) = T(n/2) + O(1)O(log n)
MergeSortT(n) = 2T(n/2) + O(n)O(n log n)

§2 Merge — unione di insiemi

Il problema Merge (unione di insiemi): dati due insiemi A e B (rappresentati come array), costruire l'insieme C = A ∪ B senza duplicati. È un buon punto di partenza per capire come la struttura dei dati e le operazioni ausiliarie influenzano la complessità.

MergeSimple — approccio naïve (slide)

Le slide scorrono prima tutti gli elementi di A, poi tutti quelli di B, usando Find lineare per evitare duplicati nell'output.

MergeSimple(A, B)
for i = 1 to length(A)
    if not Find(A[1 .. i−1], A[i])
        output A[i]
for i = 1 to length(B)
    if not Find(A, B[i]) and not Find(B[1 .. i−1], B[i])
        output B[i]

Con n = length(A) + length(B) e Find che costa O(k) su un prefisso di lunghezza k:

T(n) = ∑i=1n TFind(i) = ∑ O(i) = O(n²)
Attenzione

MergeSimple non sfrutta alcuna struttura: ogni confronto è una scansione completa. Possiamo fare molto meglio se B è ordinato.

MergeSimple2 — con Binary Search

Se B è ordinato, per ogni x ∈ A cerchiamo x in B con Binary Search in O(log m) invece di scansionare tutto B.

function MergeSimple2(A, B)    // B è ordinato
    C ← array vuoto
    for each x in A
        if not BinarySearch(B, x)    // O(log m)
            append x to C
    append all elements of B to C
    return C

Complessità totale: n chiamate a Binary Search → O(n log m). Se n ≈ m: O(n log n). Miglioramento significativo rispetto a O(n²), ma ancora non ottimale per il merge di sequenze già ordinate.

In breve

MergeSimple: doppio ciclo → O(n²). MergeSimple2: un ciclo + BS → O(n log n). La chiave è sfruttare l'ordine di B per cercare in tempo logaritmico.

§3 Binary Search

La ricerca binaria trova un elemento x in un array ordinato A[1..n] confrontando x con l'elemento centrale e scartando metà dell'array ad ogni passo.

BinarySearch(A, key)          ← versione slide
first = 1
last  = length(A)
while first ≤ last
    middle = ⌈(first + last) / 2⌉
    if A[middle] = key
        return true
    elseif first = last
        return false
    elseif A[middle] > key
        last = middle − 1
    else first = middle + 1
return false
Perché ⌈(first+last)/2⌉?
Le slide usano l'arrotondamento per eccesso per il punto medio, così l'intervallo si restringe sempre anche con 2 elementi. L'idea resta la stessa: dimezzare l'intervallo ad ogni passo.

Complessità

Ad ogni iterazione l'intervallo [p, q] si dimezza. Partendo da n elementi, servono al più ⌈log₂ n⌉ + 1 iterazioni → O(log n).

Ricorrenza
T(n) = T(n/2) + O(1) ⟹ T(n) = O(log n)

Con il Master Theorem: a=1, b=2, f(n)=O(1). Caso 1: T(n) = Θ(log n).

Spiegazione visiva

Su un array ordinato, ad ogni passo:

  1. Calcoliamo l'indice medio m = ⌊(p+q)/2⌋
  2. Confrontiamo A[m] con x: se uguale, trovato; se A[m] < x, cerchiamo a destra (p ← m+1); altrimenti a sinistra (q ← m−1)
  3. L'intervallo attivo si dimezza → al massimo log₂ n passi
Prerequisito

Binary Search funziona solo su array ordinati. Su array non ordinati non c'è modo di scartare metà degli elementi con un solo confronto.

In breve

Binary Search: dimezza l'intervallo ad ogni passo → O(log n). Prerequisito: array ordinato. È il mattoncino che rende MergeSimple2 O(n log n).

§4 Merge di sequenze ordinate

Problema diverso dall'unione di insiemi: dati due array già ordinati A[1..n] e B[1..m], costruire l'array ordinato C[1..n+m] che contiene tutti gli elementi (con duplicati se presenti).

Algoritmo Merge corretto

Usiamo due puntatori i e j. Ad ogni passo confrontiamo A[i] e B[j], mettiamo il minore in C e avanziamo il puntatore corrispondente.

function Merge(A, B)
    n ← length(A); m ← length(B)
    C ← array di dimensione n + m
    i ← 1; j ← 1; k ← 1
    while i ≤ n and j ≤ m
        if A[i] ≤ B[j]
            C[k] ← A[i]; i ← i + 1
        else
            C[k] ← B[j]; j ← j + 1
        k ← k + 1
    while i ≤ n    // copia resto di A
        C[k] ← A[i]; i ← i + 1; k ← k + 1
    while j ≤ m    // copia resto di B
        C[k] ← B[j]; j ← j + 1; k ← k + 1
    return C

Ogni elemento viene copiato esattamente una volta in C → esattamente n + m operazioni → Θ(n + m).

Perché non si può fare meglio di Θ(n)?

Limite inferiore

Per produrre l'output C[1..n+m] dobbiamo scrivere n + m elementi. Ogni scrittura richiede almeno un passo elementare → almeno Θ(n + m) operazioni. L'algoritmo Merge è quindi asintoticamente ottimo per questo problema.

Nota: MergeSimple2 era O(n log n) perché per ogni elemento di A faceva una ricerca in B. Merge «a due puntatori» sfrutta il fatto che entrambe le sequenze sono ordinate e che stiamo costruendo l'output in ordine: un solo confronto per elemento, senza bisogno di cercare.

In breve

Merge (sequenze ordinate): due puntatori, un confronto per elemento → Θ(n+m). Non si può battere Θ(n) perché l'output ha n elementi da scrivere.

§5 MergeSort

MergeSort è l'algoritmo di ordinamento per eccellenza basato su D&C. Divide l'array a metà, ordina ricorsivamente le due metà, poi le unisce con Merge.

function MergeSort(A, p, r)
    if p < r
        q ← ⌊(p + r) / 2⌋
        MergeSort(A, p, q)
        MergeSort(A, q + 1, r)
        Merge(A, p, q, r)    // combina le due metà ordinate

Analisi della complessità

Ad ogni livello di ricorsione:

  • Divide: calcolo di q → O(1)
  • Conquer: 2 sottoproblemi di dimensione n/2
  • Combine: Merge delle due metà → O(n)
T(n) = 2T(n/2) + O(n)

Con il Master Theorem (caso 2, f(n) = Θ(nlogb a logk n) con k=0): T(n) = O(n log n).

Alternativamente, l'albero di ricorsione ha log₂ n livelli; a ogni livello il lavoro totale di Merge è O(n) → O(n log n).

Non in-place

MergeSort standard non è in-place: Merge richiede un array ausiliario di dimensione O(n). Lo spazio totale è O(n) oltre all'input. Esistono varianti in-place ma con costi nascosti o peggiori nel caso peggiore.

In breve

MergeSort: dividi a metà → ordina ricorsivamente → Merge in O(n). Ricorrenza 2T(n/2)+O(n) → O(n log n). Stabile, prevedibile, ma richiede O(n) spazio extra.

§6 MergeR — merge ricorsivo

Una variante ricorsiva del merge: invece di usare due puntatori iterativi, divide entrambe le sequenze a metà e combina ricorsivamente.

function MergeR(A, B)
    if A is empty then return B
    if B is empty then return A
    n ← length(A); m ← length(B)
    A₁ ← A[1..⌊n/2⌋]; A₂ ← A[⌊n/2⌋+1..n]
    B₁ ← B[1..⌊m/2⌋]; B₂ ← B[⌊m/2⌋+1..m]
    C₁ ← MergeR(A₁, B₁)
    C₂ ← MergeR(A₂, B₂)
    return concatenate(C₁, C₂)    // ⚠ non preserva l'ordine!

Analisi: T(n,m) = T(⌊n/2⌋, ⌊m/2⌋) + T(⌈n/2⌉, ⌈m/2⌉) + O(n+m) → O(n + m) (stesso ordine di grandezza del Merge iterativo).

Esercizio — correggere MergeR

La versione sopra non produce un array ordinato: concatena C₁ e C₂ senza unire correttamente gli elementi «al centro». Ad esempio, MergeR([1,3,5], [2,4,6]) potrebbe dare [1,2,3,4,5,6] per caso, ma MergeR([1,2,3], [4,5,6]) fallisce.

Compito: correggere MergeR in modo che produca l'unione ordinata corretta, mantenendo la struttura ricorsiva e complessità O(n+m). Suggerimento: al caso base (n=1 o m=1), usa il merge elementare; oppure combina C₁ e C₂ con un Merge iterativo finale.

In breve

MergeR: merge ricorsivo O(n), ma la versione naïve con semplice concatenazione è sbagliata. Serve un passo di combinazione che rispetti l'ordine.

§7 Moltiplicazione Karatsuba

La moltiplicazione «scolastica» di due numeri di ℓ cifre richiede O(ℓ²) operazioni. Karatsuba (1960) riduce le moltiplicazioni ricorsive da 4 a 3.

Idea

Siano x e y numeri di ℓ cifre. Dividiamo ciascuno in due metà:

x = a · 10ℓ/2 + b    y = c · 10ℓ/2 + d

Allora: x · y = ac · 10ℓ + (ad + bc) · 10ℓ/2 + bd

Naïve: calcolare ac, ad, bc, bd → 4 moltiplicazioni ricorsive + O(ℓ) addizioni.

Trucco di Karatsuba: osserviamo che ad + bc = (a+b)(c+d) − ac − bd. Quindi servono solo 3 moltiplicazioni: ac, bd, e (a+b)(c+d).

function Karatsuba(x, y)
    if ℓ ≤ soglia then return moltiplicazione elementare(x, y)
    dividi x in (a, b) e y in (c, d)    // metà cifre ciascuno
    p₁ ← Karatsuba(a, c)
    p₂ ← Karatsuba(b, d)
    p₃ ← Karatsuba(a + b, c + d)
    return p₁ · 10ℓ + (p₃ − p₁ − p₂) · 10ℓ/2 + p₂

Complessità

T(ℓ) = 3T(ℓ/2) + O(ℓ)

Master Theorem, caso 2 con a=3, b=2: T(ℓ) = O(ℓlog₂ 3) ≈ O(ℓ1.585) ≈ O(ℓ1.59).

Naïve

4 mult. ricorsive → O(ℓ²)

Karatsuba

3 mult. ricorsive → O(ℓ1.59)

In breve

Karatsuba: da 4 a 3 moltiplicazioni ricorsive usando (a+b)(c+d) − ac − bd. Ricorrenza 3T(ℓ/2)+O(ℓ) → O(ℓlog₂3) ≈ O(ℓ1.59).

§8 Mediana e k-esimo elemento

Problema Selection: dato un array A[1..n] non ordinato e un intero k, trovare l'elemento che occuperebbe la posizione k se A fosse ordinato (il k-esimo più piccolo).

SimpleMedian — approccio naïve

function SimpleMedian(A)
    B ← MergeSort(A)
    return B[⌈n/2⌉]

Costo: O(n log n) per il sort + O(1) per leggere la mediana. Funziona ma è eccessivo: non ci serve l'intero array ordinato.

Ricorrenza del problema select

Se potessimo trovare la mediana esatta in O(n) e usarla come pivot (partizionamento come QuickSort), otterremmo:

T(n) = T(n/2) + O(n) ⟹ T(n) = O(n)

Nel caso peggiore (pivot sempre minimo/massimo) QuickSelect degenera a O(n²).

Ricorrenza select (slide)

Partizionando in AL, Av, AR rispetto a un pivot v:

select(A, k) =
  select(AL, k)   se k ≤ |AL|
  v   se |AL| < k ≤ |AL| + |Av|
  select(AR, k − |AL| − |Av|)   altrimenti
Esempio slide — k = 7
A = ⟨2, 36, 5, 21, 8, 13, 11, 20, 5, 4, 1⟩, pivot v = 5 → AL = ⟨2,4,1⟩, Av = ⟨5,5⟩, AR = ⟨36,21,8,13,11,20⟩.
|AL|=3, |Av|=2 → k=7 cade in AR → cerchiamo il 2° più piccolo di AR → risposta 8.

Selection con pivot casuale (slide 137)

Selection(A, k)
    v = A[random(1 .. |A|)]
    AL, Av, AR = ∅
    for i = 1 to |A|
        if A[i] < v       AL = AL ∪ {A[i]}
        elseif A[i] = v   Av = Av ∪ {A[i]}
        else            AR = AR ∪ {A[i]}
    if k ≤ |AL| return Selection(AL, k)
    elseif k > |AL| + |Av| return Selection(AR, k − |AL| − |Av|)
    else return v
function RandomizedSelect(A, p, r, k)   ← equivalente in-place
    if p = r then return A[p]
    q ← RandomPartition(A, p, r)    // pivot casuale, O(n)
    i ← q − p + 1    // rank del pivot
    if k = i then return A[q]
    else if k < i then return RandomizedSelect(A, p, q − 1, k)
    else return RandomizedSelect(A, q + 1, r, k − i)

Con pivot scelto uniformemente a caso, la dimensione del sottoproblema atteso è ≤ 3n/4 → ricorrenza attesa T(n) ≤ T(n/4) + O(n) → O(n) nel caso atteso.

Mediana della mediana

Esiste anche l'algoritmo deterministico Median-of-Medians (Blum et al.) che garantisce T(n) = O(n) nel worst case, ma è più complesso e con costanti più alte. In pratica si usa quasi sempre la versione randomizzata.

In breve

SimpleMedian: sort + leggi centro → O(n log n). RandomizedSelect: partiziona con pivot casuale → O(n) atteso. Non serve ordinare tutto l'array.

§S Soluzioni

Esercizio 1 — Soluzione

T(n) = T(n/2) + 1. Espandendo: T(n) = T(n/4) + 2 = … = T(1) + log₂ n = 1 + log₂ n.

Per n=1024 = 2¹⁰: T(1024) = 1 + 10 = 11 passi.

Esercizio 2 — Soluzione

L'albero ha ⌈log₂ 8⌉ = 3 livelli di chiamate ricorsive (più il livello base).

A ogni livello il Merge totale su tutti i sottoproblemi è O(n): livello 0 un merge da 8, livello 1 due merge da 4, livello 2 quattro merge da 2 → 8 + 4 + 4 = 16 = 2n confronti/copie. In generale: log₂ n livelli × O(n) = O(n log n).

Esercizio 3 — Soluzione 
function MergeR(A, B)
    if length(A) = 0 then return B
    if length(B) = 0 then return A
    if length(A) = 1 and length(B) = 1
        if A[1] ≤ B[1] then return [A[1], B[1]]
        else return [B[1], A[1]]
    n ← length(A); m ← length(B)
    A₁ ← A[1..⌊n/2⌋]; A₂ ← A[⌊n/2⌋+1..n]
    B₁ ← B[1..⌊m/2⌋]; B₂ ← B[⌊m/2⌋+1..m]
    C₁ ← MergeR(A₁, B₁)
    C₂ ← MergeR(A₂, B₂)
    return Merge(C₁, C₂)    // merge iterativo Θ(|C₁|+|C₂|)

Al caso base gestiamo le sequenze di lunghezza 1; la combinazione finale usa il Merge corretto a due puntatori. Complessità: T(n,m) = T(⌊n/2⌋,⌊m/2⌋) + T(⌈n/2⌉,⌈m/2⌉) + O(n+m) = O(n+m).

Esercizio 4 — Soluzione

Al primo split di numeri da ℓ=1024 cifre in due metà da 512:

  • Naïve: 4 moltiplicazioni ricorsive su numeri da 512 cifre (ac, ad, bc, bd).
  • Karatsuba: 3 moltiplicazioni ricorsive (ac, bd, (a+b)(c+d)).

Risparmio del 25% delle moltiplicazioni a ogni livello; composto su log₂ ℓ = 10 livelli porta da O(ℓ²) a O(ℓ1.59).

Esercizio 5 — Soluzione

Con pivot casuale, almeno 1/4 degli elementi finisce nel lato «sbagliato» con probabilità ≥ 1/2, quindi il sottoproblema ha dimensione ≤ 3n/4 in attesa.

Ricorrenza attesa: T(n) ≤ T(3n/4) + cn. Albero di ricorsione: n + (3/4)n + (3/4)²n + … = n · Σi≥0(3/4)i = n · 1/(1−3/4) = 4n = O(n).

Esercizio 6 — Soluzione

MergeSimple2: per ogni x ∈ A fa una ricerca in B → n ricerche × O(log m) = O(n log n). Non costruisce l'output in ordine incrementale.

Merge (sequenze ordinate): entrambe le sequenze sono ordinate e costruiamo C in ordine con due puntatori → un passo per elemento, Θ(n+m). Sfrutta la struttura dell'input in modo più profondo.
