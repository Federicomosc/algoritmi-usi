Appunti didattici completi — Antonio Carzaniga (USI, 11 marzo 2026). Partizione in-place, divide-and-conquer, binary heap e ordinamento garantito Θ(n log n).

Partition Divide & Conquer Max-Heap In-place
In parole semplici — cosa impari qui
Quick Sort ordina dividendo l'array in tre regioni rispetto a un pivot (elementi minori, uguali, maggiori), poi ricorsione sui lati. È veloce in media ma può degenerare a Θ(n²). Heap Sort usa un max-heap (albero binario quasi completo in un array) per estrarre ripetutamente il massimo: complessità Θ(n log n) nel worst case, tutto in-place.

01Panoramica — algoritmi di ordinamento

Un algoritmo di ordinamento riorganizza un array A[begin..end] in ordine non decrescente. Le slide confrontano cinque algoritmi fondamentali visti nel corso.

AlgoritmoBestAverageWorstIn-place?Note
Insertion SortΘ(n)Θ(n²)Θ(n²)SìEccellente su array quasi ordinati o piccoli
Selection SortΘ(n²)Θ(n²)Θ(n²)SìSempre Θ(n²) — pochi scambi, molti confronti
Merge SortΘ(n log n)Θ(n log n)Θ(n log n)NoStabile, richiede memoria ausiliaria Θ(n)
Quick SortΘ(n log n)Θ(n log n)Θ(n²)SìPartition + ricorsione; worst case se pivot sbilanciato
Heap SortΘ(n log n)Θ(n log n)Θ(n log n)SìWorst case garantito; non stabile
Come leggere la tabella
In-place = usa solo O(1) memoria extra oltre all'array (eventuali variabili per indici e ricorsione). Quick Sort e Heap Sort sono in-place; Merge Sort no perché il passo combine fonde in un array ausiliario. Quick Sort è il più veloce in pratica (cache-friendly), ma Heap Sort è l'alternativa in-place con worst case Θ(n log n).
Divide and Conquer — schema comune
  1. Divide — spezza il problema in sottoproblemi più piccoli
  2. Conquer — risolve ricorsivamente i sottoproblemi
  3. Combine — unisce le soluzioni parziali
Merge Sort e Quick Sort seguono questo schema; la differenza cruciale è nel passo Combine (vedi sezione 3).

02Partizione — idea e invariante

La partizione è il cuore di Quick Sort. Dato un sottoarray A[begin..end] e pivot v = A[end], riorganizza l'array in due regioni:

Due regioni (slide)
  • AL — elementi ≤ v (inclusi i duplicati del pivot)
  • AR — elementi > v
Valore restituito

Partition restituisce l'indice q del pivot nella sua posizione finale. Quick Sort ricorre su [begin..q−1] e [q+1..end] — il pivot non viene riprocessato.

Esempio concreto
Array [5, 2, 8, 2, 9, 1, 5], v = A[end] = 5 → dopo partition [5, 2, 2, 1, 5, 8, 9], q = 4. A sinistra di q tutti ≤ 5; a destra tutti > 5.

Partizione in-place — versione slide

Un solo indice q delimita AL; un ciclo for scorre i da begin a end. Se A[i] ≤ v, scambia con A[q] e avanza q. Quando i = end, il pivot viene scambiato nella posizione corretta.

Invariante del loop (slide)

All'inizio di ogni iterazione con indice i:

begin ≤ k < q ⇒ A[k] ≤ v   |   q ≤ k < i ⇒ A[k] > v

Gli elementi in [i..end] non sono ancora stati classificati.

Partition(A, begin, end)
    q = begin
    v = A[end]
    for i = begin to end
        if A[i] ≤ v
            scambia A[i] con A[q]
            q = q + 1
    return q − 1
Perché funziona senza swap finale?
Quando i = end, abbiamo A[end] = v. La condizione A[i] ≤ v è vera, quindi il pivot viene scambiato con A[q] nell'ultima iterazione e finisce in posizione q−1.

03Quick Sort — ricorsione e combine

Quick-Sort(A, begin, end)
    if begin < end
        q = Partition(A, begin, end)
        Quick-Sort(A, begin, q − 1)
        Quick-Sort(A, q + 1, end)
Quick Sort — Combine

Combine = niente! La partition riorganizza l'array in-place: quando le due chiamate ricorsive terminano, l'intero sottoarray è già ordinato. Nessun merge ausiliario.

Merge Sort — Combine

Combine = Merge(A, p, q, r) — fonde due metà già ordinate in un array temporaneo. Costo Θ(n) per livello, memoria extra Θ(n).

Albero di ricorsione
Ogni chiamata a Partition produce un pivot in posizione definitiva. Le chiamate ricorsive lavorano su porzioni sempre più piccole. Se ogni partition è bilanciata (circa metà elementi per lato), l'albero ha altezza Θ(log n) → complessità totale Θ(n log n).

04Complessità di Quick Sort

ProceduraComplessitàQuando
Partition(A, begin, end)Θ(n)Scansiona una volta tutti gli elementi del sottoarray
Quick-Sort — best caseΘ(n log n)Partition bilanciata: q ≈ metà del sottoarray ad ogni livello
Quick-Sort — worst caseΘ(n²)Partition sbilanciata: q = begin−1 o q = end ad ogni livello
Quick-Sort — averageΘ(n log n)Pivot scelto in modo ragionevole (random, median-of-three)
Worst case — partition sempre sbilanciata
Se il pivot è sempre il minimo o il massimo (es. array già ordinato con pivot = ultimo elemento), una partizione risolve un solo elemento e lascia un sottoarray di n−1 elementi. Si ottengono n livelli di ricorsione, ciascuno con partition Θ(n) → Θ(n²) totale.
Ricorrenza (partition bilanciata)
T(n) = 2T(n/2) + Θ(n) ⟹ T(n) = Θ(n log n)

Per il caso peggiore: T(n) = T(n−1) + Θ(n) ⟹ T(n) = Θ(n²).

— Binary Heap & Heap Sort —

05Binary Heap — rappresentazione ad array

Un binary heap è un albero binario quasi completo memorizzato in un array A con attributo A.heap-size (quanti elementi dell'heap sono attivi).

Formule indici (array 1-based)
  • Parent(i) = ⌊i/2⌋
  • Left(i) = 2i
  • Right(i) = 2i + 1
Proprietà max-heap
Per ogni nodo i > 1:
A[Parent(i)] ≥ A[i]
Il massimo è sempre in A[1] (radice).
Interfaccia heap (slide) — operazioni principali
  • Max-Heapify(A, i) — ripristina max-heap sul sottoalbero in i · Θ(log n)
  • Build-Max-Heap(A) — costruisce heap da array arbitrario · O(n)
  • Heap-Insert(A, x) — inserisce x e «risale» con swap verso la radice · Θ(log n)
  • Heap-Extract-Max(A) — rimuove il massimo (radice), mette l'ultimo elemento in radice e heapify · Θ(log n)

Min-heap: stessa struttura, proprietà A[Parent(i)] ≤ A[i] — il minimo è in A[1]. Priority queue: un heap implementa una coda con priorità: inserimento e estrazione del massimo (o minimo) in tempo logaritmico.

Esempio
Array [16, 14, 10, 8, 7, 9, 3, 2, 4, 1] con heap-size 10. Radice 16 ≥ figli 14 e 10; ogni sottoalbero rispetta la proprietà max-heap.

06Max-Heapify

Max-Heapify(A, i) ripristina la proprietà max-heap quando il sottoalbero radicato in i potrebbe violarla (tipicamente dopo uno scambio).

Max-Heapify(A, i)
    l = Left(i)
    r = Right(i)
    if l ≤ A.heap-size and A[l] > A[i]
        largest = l
    else largest = i
    if r ≤ A.heap-size and A[r] > A[largest]
        largest = r
    if largest ≠ i
        scambia A[i] con A[largest]
        Max-Heapify(A, largest)

Complessità: Θ(log n) — percorre al più un cammino dalla radice a una foglia (altezza dell'albero).

07Build-Max-Heap

Build-Max-Heap(A)
    A.heap-size = A.length
    for i = ⌊A.length/2⌋ down to 1
        Max-Heapify(A, i)
Perché partire da ⌊n/2⌋?
I nodi da ⌊n/2⌋+1 a n sono foglie — già heap banali. Si heapifica dal basso verso l'alto. Complessità totale: O(n) (non O(n log n)!), per analisi ammortizzata sulle altezze dei nodi.

08Heap Sort

Heap-Sort(A)
    Build-Max-Heap(A)
    for i = A.length down to 2
        scambia A[1] con A[i]
        A.heap-size = A.heap-size − 1
        Max-Heapify(A, 1)
Complessità Heap Sort
  • Build-Max-Heap: O(n)
  • Loop n−1 volte: scambio O(1) + Max-Heapify Θ(log n)
  • Totale worst case: Θ(n log n), in-place (solo l'array + heap-size)
Idea in una frase
Estrai ripetutamente il massimo (radice) e mettilo in fondo all'array; riduci heap-size e ripristina l'heap sul resto. Alla fine l'array è ordinato in ordine crescente.

E2Soluzioni dettagliate

Esercizio 1 — Partition

Pivot v=7. q parte da 0. Ogni A[i] ≤ 7 fa swap con A[q] e q++: dopo i=4 abbiamo q=5, array invariato (ogni swap è con se stesso finché non arriviamo al pivot).

i=5: swap A[5]↔A[5] → q=6. return q−1 = 5. Tutti gli elementi sono ≤ 7, nessun AR; il pivot resta in A[5].

Esercizio 2 — Indici heap

Parent(5) = ⌊5/2⌋ = 2. Left(3) = 6, Right(3) = 7.

Foglie: nodi ⌊10/2⌋+1 = 6 … 10. Foglia più a sinistra: nodo 6.

Esercizio 3 — Worst case Quick Sort

Array ordinato crescente, pivot = ultimo = massimo → tutti gli elementi < pivot → q = end, sottoarray sinistro ha n−1 elementi, destro vuoto. Ricorsione solo a sinistra, profondità n.

n=4: partition costa 4+3+2+1 = 10 = Θ(n²). Albero: catena lineare di 4 nodi.

Esercizio 4 — Merge vs Quick vs Heap

Merge: Θ(n log n) sempre, Θ(n) spazio, stabile, combine = merge.

Quick: Θ(n log n) avg, Θ(n²) worst, in-place, combine = nulla, instabile.

Heap Sort quando serve worst Θ(n log n) in-place senza rischio quadratico (embedded, real-time).

Esercizio 5 — Max-Heapify(A,1)

Confronto figli di 1: Left=2 (1), Right=3 (3) — largest=3. Swap A[1]↔A[3] → [3,1,4,…]. Ricorsione su nodo 3: figli 6 (9), 7 (10) — swap con 10 → [3,1,10,2,16,9,4,14,8,7]. Stop.

Esercizio 6 — Build-Max-Heap

⌊7/2⌋=3. Heapify i=3,2,1. Dopo i=3: [4,1,3,2,16,9,10]. Dopo i=2: ok. Dopo i=1: swap e discendi → [16, 4, 10, 2, 1, 9, 3].

Esercizio 7 — Heap Sort [4,1,3,2]

Build-Max-Heap → [4, 2, 3, 1]. i=4: swap → [1, 2, 3, 4], heap-size=3, heapify → [3, 2, 1, 4]. i=3: swap → [1, 2, 3, 4], heap-size=2, heapify → [2, 1, 3, 4]. i=2: swap → [1, 2, 3, 4]. Ordinato.

Esercizio 8 — Ricorrenze

Master theorem: a=2, b=2, f(n)=cn → T(n)=Θ(n log n).

Build-Max-Heap: somma su nodi di altezza h di O(2^h · (log n − h)) = O(n) — molti nodi bassi, pochi alti.
