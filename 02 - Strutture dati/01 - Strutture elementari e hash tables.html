LIFO / FIFO Sentinel Chaining Open Addressing
In parole semplici — cosa impari qui
Prima impari come organizzare i dati (stack, coda, lista), poi come implementare un dizionario (insieme di chiavi con Insert/Delete/Search). La direct-address table è velocissima ma spreca memoria; le hash table comprimono l'universo delle chiavi in una tabella piccola, gestendo le collisioni con liste (chaining) o con ricerca di celle libere (open addressing).

01Concetti e notazione comune

Definizione — Struttura dati
Una struttura dati è un modo di organizzare e memorizzare informazioni per facilitarne l'accesso (o per altri scopi).

Ogni struttura dati ha:

  • Interfaccia — procedure per aggiungere, eliminare, accedere, riorganizzare, ecc.
  • Implementazione — come i dati sono effettivamente memorizzati in memoria
  • Dati + metadati — es. un heap usa l'array A più la variabile A.heap-size
Distinzione fondamentale
ADT (Abstract Data Type) = cosa fa (interfaccia). Struttura dati concreta = come lo fa (array, lista, albero…). Lo stesso ADT può avere implementazioni diverse con complessità diverse.
Esempio quotidiano
Un dizionario (ADT) dice: «cerca una parola, aggiungila, cancellala». Puoi implementarlo con un array ordinato (ricerca lenta), un albero, o una hash table (ricerca veloce in media). L'interfaccia è la stessa; cambia solo il «motore» sotto.

02Stack — LIFO

Il container «last-in first-out» più universale — come una pila di piatti: aggiungi e togli sempre dall'alto.

Interfaccia
  • Stack-Empty(S) — true se e solo se S è vuoto
  • Push(S, x) — inserisce x in cima
  • Pop(S) — estrae e restituisce l'elemento in cima

Implementazione con array

Lo stack è un array S con puntatore S.top alla posizione dell'elemento in cima. Inizialmente S.top = 0 (stack vuoto).

Stack-Empty(S)
if S.top == 0
    return true
else return false

Push(S, x)
S.top = S.top + 1
S[S.top] = x

Pop(S)
if Stack-Empty(S)
    error "underflow"
else
    S.top = S.top − 1
    return S[S.top + 1]
Underflow vs Overflow
Underflow = Pop su stack vuoto. Overflow = Push quando l'array è pieno (se ha dimensione fissa). Con array dinamico si ridimensiona, ma il resize ha costo ammortizzato.

Complessità: tutte le operazioni sono O(1).

Implementazione con lista concatenata

Le slide menzionano anche una implementazione con lista concatenata: Push = List-Insert in testa, Pop = accesso al primo nodo + List-Delete. Anche qui tutte le operazioni sono O(1), senza rischio di overflow (a differenza dell'array a dimensione fissa).

Array vs lista
Array: accesso cache-friendly, ma overflow se pieno. Lista: crescita illimitata, ma ogni nodo ha overhead di puntatori prev/next.

03Queue — FIFO

Come la coda al supermercato: chi arriva prima esce prima. head indica chi sta per essere servito; tail indica dove si mette in fila il prossimo arrivato.

Head e tail — esempio concreto
Coda [A, B, C] in array circolare: head punta ad A (prossimo Dequeue), tail punta alla prima cella vuota dopo C (prossimo Enqueue). Dopo Dequeue, head avanza e A esce; la cella di A può essere riusata quando tail la raggiunge — ecco perché serve l'avvolgimento circolare.
Interfaccia
  • Enqueue(Q, x) — aggiunge x in fondo alla coda
  • Dequeue(Q) — estrae l'elemento in testa

Implementazione con array circolare

La coda ha lunghezza fissa Q.length. Due puntatori:

  • Q.head — posizione della testa (prossimo Dequeue)
  • Q.tail — prima posizione vuota in fondo (prossimo Enqueue)
  • Flag queue-full e queue-empty per distinguere pieno/vuoto quando head = tail
Enqueue(Q, x)
if Q.queue-full
    error "overflow"
else
    Q[Q.tail] = x
    if Q.tail < Q.length
        Q.tail = Q.tail + 1
    else Q.tail = 1          ← avvolgimento circolare
    if Q.tail == Q.head
        Q.queue-full = true
    Q.queue-empty = false

Dequeue(Q)
if Q.queue-empty
    error "underflow"
else
    x = Q[Q.head]
    if Q.head < Q.length
        Q.head = Q.head + 1
    else Q.head = 1
    if Q.tail == Q.head
        Q.queue-empty = true
    Q.queue-full = false
    return x
Perché circolare?
Senza avvolgimento, dopo molti Dequeue le posizioni 1…head−1 restano inutilizzate («drift»). L'array circolare riusa tutte le celle → O(1) per Enqueue e Dequeue senza sprecare spazio.

Complessità: Enqueue e Dequeue sono O(1).

04Liste concatenate (doubly-linked con sentinella)

Interfaccia
  • List-Insert(L, x) — inserisce x all'inizio della lista
  • List-Delete(L, x) — rimuove l'elemento x dalla lista
  • List-Search(L, k) — trova un elemento con chiave k

Ogni elemento x ha: x.key, x.prev, x.next. La sentinella L.nil è un nodo fittizio che non contiene dati utili: fa da «ancora» così la lista non ha mai testa «nulla».

Sentinella — perché serve?
Senza sentinella, lista vuota = puntatore null → ogni Insert deve gestire un caso speciale. Con L.nil, lista vuota significa L.nil.next = L.nil (il sentinella punta a sé stesso). Insert e Delete usano sempre gli stessi 4 passi, senza if lista vuota. 
List-Init(L)
L.nil.prev = L.nil
L.nil.next = L.nil

List-Insert(L, x)          ← inserisce in testa, O(1)
x.next = L.nil.next
L.nil.next.prev = x
L.nil.next = x
x.prev = L.nil

List-Search(L, k)          ← O(n) worst-case
x = L.nil.next
while x ≠ L.nil and x.key ≠ k
    x = x.next
return x

List-Delete(L, x)          ← O(1) dato il puntatore a x
x.prev.next = x.next
x.next.prev = x.prev

06Dizionario (Dictionary)

ADT — Dizionario
Un dizionario è una struttura astratta che rappresenta un insieme dinamico di chiavi.
  • Insert(D, k) — aggiunge la chiave k
  • Delete(D, k) — rimuove k
  • Search(D, k) — verifica se k è presente

Implementazioni concrete: alberi bilanciati, hash table, array ordinato (con binary search), ecc.

07Direct-Address Table

Universo delle chiavi: U = {1, 2, …, M}. Tabella T[1..M]: la chiave k va direttamente in posizione T[k].

Direct-Address-Insert(T, k)
T[k] = true

Direct-Address-Delete(T, k)
T[k] = false

Direct-Address-Search(T, k)
return T[k]
Vantaggio
Tutte le operazioni sono O(1) — accesso diretto come un array indicizzato dalla chiave stessa.
Svantaggio
Spazio Θ(|U|). Se U = tutti i possibili indirizzi IP (2³²) ma memorizzi 100 chiavi, sprechi gigabyte. |U| è enorme, il set è piccolo.

Domanda delle slide: possiamo avere i benefici dell'accesso diretto con una tabella di dimensione ragionevole? → Sì, con le hash table.

08Hash Table — Idea e collisioni

Analogia — casellario postale
Hai migliaia di persone (universo U) ma solo 100 caselle (tabella T). La funzione hash h(k) dice in quale casella mettere la chiave k. Due persone diverse possono finire nella stessa casella → collisione. Chaining: nella casella tieni una lista di tutti gli occupanti. Open addressing: se la casella è piena, provi la successiva libera.
Idea
Usa una tabella T con |T| ≪ |U|. Funzione hash h : U → {1, …, |T|} mappa ogni chiave in una posizione. 
← Versione ingenua (SBAGLIATA con collisioni)
Hash-Insert(T, k)
T[h(k)] = true

Hash-Search(T, k)
return T[h(k)]
Le slide chiedono: «Are these algorithms correct?»
No! Se h(k₁) = h(k₂) con k₁ ≠ k₂ (collisione), inserire k₂ sovrascrive k₁ nella stessa cella. Search restituisce solo un booleano per slot, non distingue le chiavi. Delete di k₂ cancellerebbe anche k₁. Serve una strategia di risoluzione delle collisioni.
Esempio collisione (slide)
Con U = {k₁, k₂, k₃, k₄} e |T| = 4, se h mappa k₁ e k₃ nello stesso bucket e k₂, k₄ in un altro, la versione ingenua perde informazione. Il chaining mantiene liste separate: T[h(k₁)] → k₃ → k₁, ecc.

Mini-animazione SVG — Collisioni hash (naive vs chaining)

Con h(k) = k mod 7 e |T| = 7. Prima vedi la versione ingenua che perde chiavi, poi il chaining che le concatena nella stessa lista.

Chaining (concatenamento)

Ogni cella T[i] punta a una lista concatenata di tutte le chiavi con hash i.

Chained-Hash-Insert(T, k)
return List-Insert(T[h(k)], k)

Chained-Hash-Search(T, k)
return List-Search(T[h(k)], k)

Chained-Hash-Delete(T, k)
List-Delete(T[h(k)], x)    ← x = elemento trovato da Search

Load factor: α = n / |T|

Open Addressing (indirizzamento aperto)

Tutte le chiavi stanno nella tabella (niente liste esterne) → richiede α ≤ 1. In caso di collisione si cerca un'altra cella libera.

← Linear probing (probing sequenziale)
Hash-Insert(T, k)
j = h(k)
for i = 1 to T.length
    if T[j] == nil
        T[j] = k
        return j
    elseif j < T.length
        j = j + 1
    else j = 1
error "overflow"

← Probing generale: h(k, i) per i = 1..|T|
Hash-Insert(T, k)
for i = 1 to T.length
    j = h(k, i)
    if T[j] == nil
        T[j] = k
        return j
error "overflow"
Proprietà di h(k, ·)
La sequenza h(k,1), h(k,2), …, h(k,|T|) deve essere una permutazione di tutte le posizioni {1,…,|T|} — così ogni cella viene provata esattamente una volta e, se esiste una cella libera, Insert la trova in al più |T| passi.
Perché il probe sequenziale «non è ottimale»?
Le slide lasciano come esercizio il primary clustering: se due chiavi collidono in j, entrambe cercano celle consecutive j, j+1, j+2… Le zone piene si «allungano» e le ricerche successive attraversano catene sempre più lunghe, anche per chiavi con hash diversi.

Search e Delete in open addressing seguono la stessa sequenza di probe di Insert: per trovare k si visita h(k,1), h(k,2), … finché si trova k o una cella nil (assente). Delete richiede attenzione (marcatori «deleted») per non interrompere le catene di probe — dettaglio oltre le slide, ma utile in implementazioni reali.

09Analisi — Uniform hashing e α

Assunzione — Simple Uniform Hashing
Pr[h(k) = i] = 1/|T|   per ogni i ∈ {1, …, |T|}
Ogni posizione ha uguale probabilità. (Il formalismo completo è più sofisticato, ma l'intuizione è questa.)
Risultato chiave (chaining)
Con n chiavi distinte, la lunghezza attesa della lista in posizione i è:
E[nᵢ] = n/|T| = α
Assumendo h(k) computabile in O(1):
Chained-Hash-Search = Θ(1 + α)
Chained-Hash-Insert e Chained-Hash-Delete sono anch'essi Θ(1 + α) in tempo atteso (Search + O(1) per List-Insert/Delete).

Dimostrazione intuitiva di E[nᵢ] = α

  1. Sotto uniform hashing, ogni chiave ha probabilità 1/|T| di finire nel bucket i.
  2. Definiamo la variabile indicatrice Xⱼ = 1 se la chiave j va in i, 0 altrimenti. Allora E[Xⱼ] = 1/|T|.
  3. La lunghezza della lista in i è nᵢ = Σⱼ Xⱼ (somma su n chiavi distinte).
  4. Per linearità del valore atteso: E[nᵢ] = Σⱼ E[Xⱼ] = n · (1/|T|) = n/|T| = α.
Scelta di |T|
Se mantieni α = O(1) (es. α ≤ 1 o α ≤ 2), le operazioni hash sono O(1) in tempo atteso. Se raddoppi n, raddoppia |T| per mantenere α costante.
α in una frase
Se α = 2, in media ogni casella del casellario ha 2 chiavi nella lista. Cercare una chiave costa 1 accesso alla casella + ~2 confronti nella lista ≈ 3 passi in media. Ecco perché Search = Θ(1 + α).

E2Soluzioni dettagliate

Esercizio 1 — Traccia Stack

Push(3): top=1, [3]. Push(7): top=2, [3,7]. Pop→7: top=1, [3]. Push(1): top=2, [3,1]. Pop→1: top=1, [3]. Pop→3: top=0, [].

Un ulteriore Pop() su stack vuoto causa underflow (errore).

Esercizio 2 — Traccia Queue

Dopo A,B,C: head=1, tail=4, coda [A,B,C]. Dequeue→A: head=2, tail=4, [B,C]. Enqueue D: head=2, tail=1 (avvolgimento), [B,C,D]. Enqueue E: head=2, tail=2, coda piena [B,C,D,E].

Il prossimo Enqueue darebbe overflow.

Esercizio 3 — List-Search

Worst-case: k assente o nell'ultimo nodo → il ciclo visita tutti i n elementi → Θ(n).

Best-case: k in testa → Θ(1).

Esercizio 4 — Collisioni

h(12)=2, h(22)=2, h(32)=2, h(5)=5, h(15)=5.

Con insert in testa: T[2]→32→22→12, T[5]→15→5.

n=5, |T|=10 → α=0,5. Worst-case Search: bucket T[2] con 3 elementi → costo 3 confronti → Θ(3) = Θ(1+α) localmente peggiore del medio.

Esercizio 5 — Spazio

Direct-address: Θ(10⁶) celle, indipendentemente da n=500.

Hash: Θ(1000) bucket + liste; con n=500, α=0,5 → Search atteso Θ(1,5). La direct-address spreca ~999500 celle vuote.

Esercizio 6 — E[nᵢ]

E[nᵢ] = n/|T| = 20/5 = 4 = α. Costo atteso Search = 1 + α = 5 confronti.

Se n raddoppia (α=8), il costo atteso diventa 1+8=9: raddoppiare le chiavi senza ridimensionare la tabella degrada le prestazioni linearmente in α.

Esercizio 7 — Due stack

Enqueue: Push su stack in. Dequeue: se stack out vuoto, trasferisci tutto da in a out (invertendo ordine); poi Pop da out.

Enqueue O(1). Dequeue O(1) ammortizzato: ogni elemento si sposta al più una volta.

Esempio Enq 1,2,3,4 poi Deq: out riceve 4,3 dopo trasferimento; Deq→4; secondo Deq→3 senza nuovo trasferimento.

Esercizio 8 — Open addressing

h(1)=1→T[1]. h(6)=1 occupato→T[2]. h(11)=1→T[3]. h(2)=2 occupato→T[4]. h(7)=2→T[5] (tabella piena).

Stato finale: [1,6,11,2,7] — catena 1→2→3… da collisioni su slot 1 e 2.

Clustering: le collisioni creano blocchi contigui; permutazione: la sequenza di probe deve coprire tutta T, altrimenti Insert potrebbe non trovare celle libere esistenti.
