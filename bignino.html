Bignino completo — Algoritmi

Tutto il corso in forma schematica: definizioni, formule, ricorrenze, pseudocodice e complessità. Una riga = un concetto. Pensato per il ripasso finale: se un punto non ti dice nulla, apri il capitolo completo dall'indice.

01Analisi della complessità

Modello RAM

  • Ogni passo elementare (assegnamento, confronto, +, −, ×, accesso array, return) costa O(1).
  • Si contano i passi in funzione di n = dimensione dell'input.
  • Si ignorano i fattori costanti e i termini di ordine inferiore → conta solo la crescita asintotica.

Come si misura

Worst-case = massimo numero di passi su input di taglia n (è quello standard). Best/average raramente richiesti.
Ciclo singolo su n → Θ(n) · doppio ciclo annidato → Θ(n²) · dimezzare a ogni passo → Θ(log n) · dividi+ricorsione → spesso Θ(n log n).

Notazioni asintotiche

Regola pratica: tieni solo il termine dominante, butta le costanti. 3n²+10n+100 = Θ(n²).

Gerarchia di crescita (dal più lento al più veloce a crescere)

1 < log n < √n < n < n log n < n² < n³ < 2ⁿ < n! < nⁿ

01bP, NP, NP-completezza

ClasseDefinizione (problemi decisionali, risposta SÌ/NO)
PRisolvibile da un algoritmo in tempo polinomiale O(n^k).
NPDato un certificato (soluzione candidata), esiste un verificatore polinomiale che controlla se è valido.
NP-hardOgni problema di NP si riduce ad esso in tempo polinomiale (almeno difficile come tutti in NP).
NP-completoÈ in NP ed è NP-hard (il "più difficile" di NP).
P ⊆ NP (se sai risolverlo, sai verificarlo). P = NP? resta aperto.
Riduzione A ≤ₚ B: trasformo istanze di A in istanze di B in tempo poly preservando la risposta SÌ/NO. Se B è facile, anche A lo è.
SAT (soddisfacibilità di formula booleana) è stato il primo problema NP-completo (Cook–Levin).

Esempi del corso

  • SAT / 3-CNF-SAT → NP-completo.
  • 2-CNF-SAT ∈ P: riducilo a raggiungibilità su un grafo delle implicazioni (ogni clausola a∨b → due implicazioni ¬a→b e ¬b→a). Insoddisfacibile ⟺ esiste x con x e ¬x nella stessa componente fortemente connessa.
  • Vertex Cover (VC) → NP-completo (versione decisionale: esiste un cover di taglia ≤ k?).
All'esame

«Mostra che X ∈ P» → dai l'algoritmo e analizza la complessità. «Mostra che X ∈ NP» → descrivi il certificato e un verificatore polinomiale Verify(istanza, certificato). NP non significa "impossibile".

02Strutture dati elementari & hash

Stack — LIFO. Push/Pop/Top O(1). Array+top o lista.
Queue — FIFO. Enqueue/Dequeue O(1). Array circolare (head/tail) o lista.
Lista doppiamente concatenata con sentinella L.nil: evita i casi limite (lista vuota / primo / ultimo). Insert/Delete O(1) se hai il puntatore al nodo; Search O(n).

Dizionario & hash

  • Dizionario: Insert / Delete / Search per chiave.
  • Direct-address table: array indicizzato dalla chiave. O(1) ma spreca spazio se l'universo è grande.
  • Hash table: funzione h(k) mappa chiavi → slot. Collisione = due chiavi nello stesso slot.
Chaining — ogni slot è una lista delle collisioni. Search medio Θ(1+α), worst O(n).
Open addressing — niente liste: cerca lo slot libero successivo (linear/quadratic probing, double hashing).
Load factor α = n/m (elementi / slot). Con uniform hashing il numero medio di elementi per slot è E[nᵢ] = α → search media Θ(1+α). Tieni α costante (≈ O(1)).

Insertion sort — correttezza con invariante di ciclo

  • Invariante: all'inizio dell'iterazione i, A[1..i−1] è ordinato e contiene gli stessi elementi iniziali.
  • Inizializzazione (i=2): A[1..1] è banalmente ordinato. Mantenimento: inserire A[i] al posto giusto mantiene l'ordine. Terminazione (i=n+1): A[1..n] ordinato.
  • Worst case = array decrescente: confronti = (n−1)·n/2 = Θ(n²) (serie aritmetica).

Quick Sort — Partition

  • Partition(A,p,r): pivot = A[r]; scorri e porta a sinistra ciò che è ≤ pivot; metti il pivot al confine. Restituisce l'indice del pivot. Costo Θ(n).
  • Worst Θ(n²) quando il pivot è sempre il min/max (es. array già ordinato): partizioni sbilanciate (0, n−1).
  • Avg Θ(n log n) con pivot bilanciato; pivot casuale rende il worst improbabile.

Heap (binario, max-heap come array)

  • Array: parent(i)=⌊i/2⌋, left(i)=2i, right(i)=2i+1.
  • Proprietà max-heap: A[parent(i)] ≥ A[i]. (radice = massimo)
  • Max-Heapify(i): fa "scendere" un nodo che viola la proprietà → O(log n).
  • Build-Max-Heap: Heapify dal centro alle radici → O(n) (non n log n!).
  • Heap Sort: build (O(n)) + n volte (scambia radice con ultimo, riduci heap, heapify) → Θ(n log n).

03bDivide & Conquer + Master Theorem

Schema D&C: 1) Divide in sottoproblemi · 2) Conquer ricorsivamente · 3) Combine i risultati.

Master Theorem — T(n) = a·T(n/b) + f(n)

Confronta f(n) con n^(log_b a) (= c):

CasoCondizioneRisultato
1f(n) = O(n^(c−ε)) — domina la ricorsioneΘ(n^c)
2f(n) = Θ(n^c · logᵏn)Θ(n^c · log^(k+1) n)
3f(n) = Ω(n^(c+ε)) — domina f (+ regolarità)Θ(f(n))

Pezzi chiave

  • Binary Search: array ordinato; confronta col centro, scarta metà → Θ(log n).
  • Merge di 2 sequenze ordinate: due indici, prendi il minore in testa → Θ(n). Non si può fare meglio di Θ(n): bisogna toccare tutti gli elementi.
  • Karatsuba: moltiplicazione scolastica O(ℓ²) → riduce da 4 a 3 moltiplicazioni ricorsive usando ad+bc = (a+b)(c+d) − ac − bd.
  • Mediana / k-esimo (Select): con pivot (Quickselect) → O(n) atteso. Naïve (ordina) → O(n log n).

04Binary Search Tree (BST)

Proprietà BST: per ogni nodo x → tutto il sottoalbero sinistro ≤ x.key ≤ tutto il sottoalbero destro.

Visite (tree-walk)

  • In-order (sx, nodo, dx) → chiavi in ordine crescente. Reverse-order = decrescente.
  • Pre-order (nodo, sx, dx) · Post-order (sx, dx, nodo). Tutte Θ(n).

Operazioni — tutte Θ(h)

  • Search: scendi a sinistra se k < key, a destra se k > key.
  • Minimum / Maximum: scendi sempre a sinistra / destra.
  • Successor: se ha sottoalbero dx → minimo del dx; altrimenti risali finché non sei figlio sinistro.
  • Insert: scendi come in search fino a una foglia, appendi lì.

Delete — 3 casi

  1. 0 figli (foglia): rimuovi.
  2. 1 figlio: sostituisci il nodo col figlio.
  3. 2 figli: sostituisci col successore (minimo del sottoalbero destro), poi rimuovi il successore.
Altezza

h = Θ(log n) se bilanciato, ma degenera a Θ(n) (catena) se inserisci dati ordinati. Soluzioni: inserimento randomizzato, root-insert con rotazioni, o alberi bilanciati (Red-Black).

Range query [a,b]: pota i rami impossibili — se key<a vai solo a destra, se key>b vai solo a sinistra. Con campo size nei nodi conti gli elementi in O(h) senza visitare tutto.

04bRed-Black Tree & B-tree

Red-Black — 5 proprietà

  1. Ogni nodo è rosso o nero.
  2. La radice è nera.
  3. Ogni foglia (T.nil) è nera.
  4. Un nodo rosso ha entrambi i figli neri (mai due rossi consecutivi).
  5. Black-height uguale: ogni cammino da un nodo alle foglie ha lo stesso numero di nodi neri.
Garantisce h ≤ 2·log₂(n+1) = O(log n) → tutte le operazioni O(log n). Si dimostra: size ≥ 2^bh − 1 e bh ≥ h/2.
Rotazioni (LEFT/RIGHT-ROTATE, O(1)) ribilanciano localmente preservando la proprietà BST.

RB-Insert-Fixup — casi (nodo z rosso)

  • Genitore nero → nessun fixup.
  • Zio rosso → ricolora genitore+zio neri, nonno rosso, risali (itera sul nonno).
  • Zio nero → rotazione (zig-zag prima si raddrizza, poi rotazione singola) + ricolorazione. Termina.

B-tree — ricerca su memoria secondaria

  • Motivazione: un accesso a disco (Disk-Read) costa ~10⁴–10⁷ cicli CPU. Si minimizza il numero di accessi = altezza → nodi "grassi" con molte chiavi.
  • Grado minimo t ≥ 2: ogni nodo (≠ radice) ha tra t−1 e 2t−1 chiavi, e tra t e 2t figli. Nodo pieno = 2t−1 chiavi.
  • Altezza: h ≤ log_t((n+1)/2) → O(log_t n) accessi disco.
  • Search: in ogni nodo scegli l'intervallo giusto fra le chiavi → O(t·log_t n) CPU, O(log_t n) Disk-Read.
  • Insert: scendi e spezza (split) ogni nodo pieno che incontri: la chiave mediana sale al padre. L'albero cresce in altezza solo quando si spezza la radice (raro).

05Grafi — rappresentazione, BFS, DFS, topo

Rappresentazione

SpazioArco (u,v)?Itera viciniQuando
Lista adiacenzaΘ(V+E)O(grado)O(grado)grafo sparso
Matrice adiacenzaΘ(V²)O(1)O(V)grafo denso

Non orientato: ogni arco appare 2 volte / matrice simmetrica. Σ gradi = 2E.

BFS — ampiezza · O(V+E)

  • Usa una coda (FIFO), esplora livello per livello. Colori WHITE→GRAY→BLACK.
  • Calcola d[v] = distanza in numero di archi da s → cammino minimo su grafi non pesati.
  • Albero BFS: π[v] = predecessore.

DFS — profondità · O(V+E)

  • Ricorsione / stack. Timestamp d[v] (scoperta) e f[v] (fine). Colori WHITE/GRAY/BLACK.
  • Ciclo esterno su tutti i vertici → foresta DFS.
  • Classifica archi: tree / back (→ ciclo) / forward / cross.

Ordinamento topologico (DAG)

  • Esegui DFS; inserisci ogni vertice in testa a una lista quando lo finisci (ordine decrescente di f[v]). O(V+E).
  • Valido solo su DAG (grafo orientato aciclico).
Componenti connesse: ripeti BFS/DFS su ogni vertice ancora WHITE.

05bMST (Kruskal, Prim) & Dijkstra

MST = sottoinsieme di archi che connette tutti i vertici con peso totale minimo (è un albero, V−1 archi). Definito su grafi non orientati pesati e connessi.

Teorema del taglio (base di entrambi)

Cut property: per ogni taglio che non attraversa archi già scelti, l'arco di peso minimo che attraversa il taglio (safe edge) appartiene a qualche MST.

Kruskal — O(E log E)

  • Ordina gli archi per peso crescente.
  • Scorri: aggiungi l'arco se non crea ciclo (controllo con Union-Find).
  • Union-Find (disjoint-set): Find = radice dell'insieme, Union = unisce due insiemi. Quasi O(1) ammortizzato.
  • Bene su grafi sparsi.

Prim — O((V+E) log V) con heap

  • Cresce un solo albero da un vertice radice.
  • Mantieni per ogni vertice fuori dall'albero il peso minimo W[v] di un arco verso l'albero e il predecessore P[v].
  • Estrai il vertice con W minimo (min-priority queue), aggiungilo, aggiorna (relax) i suoi vicini. Bene su grafi densi.

Dijkstra — cammini minimi da sorgente · O((V+E) log V)

  • Quasi identico a Prim, ma rilassa sulla distanza dalla sorgente, non sul peso del singolo arco.
  • Variabili: D[v] = distanza stimata da s, P[v] = predecessore, N = insieme dei finalizzati.
  • Relax(u,v): if D[u]+w(u,v) < D[v] then D[v]=D[u]+w(u,v); P[v]=u.
  • Estrai il vertice con D minima, finalizzalo, rilassa i vicini. Greedy: una volta estratto, D[v] è definitiva.
Limite

Dijkstra richiede pesi ≥ 0. Con archi negativi usa Bellman-Ford (O(V·E), rileva cicli negativi).

06Greedy (algoritmi voraci)

Greedy = a ogni passo la scelta localmente ottima, senza tornare indietro. Funziona se valgono greedy-choice property (la scelta locale fa parte di un'ottima globale) e optimal substructure.

Quando funziona / quando no

Greedy ottimo ✓Greedy fallisce → serve DP ✗
Activity selection (non pesata)Weighted activity selection
Huffman codingKnapsack 0-1
Knapsack frazionarioLIS, edit distance
MST (Kruskal/Prim), DijkstraResto monete (sistemi "strani")

Esempi chiave

  • Activity selection: ordina per earliest finish time, prendi ogni attività compatibile con l'ultima scelta. Ottimo (exchange argument). O(n log n).
  • Knapsack frazionario: ordina per valore/peso (vᵢ/wᵢ) decrescente, riempi; l'ultimo oggetto si può spezzare. Greedy ottimo.
  • Knapsack 0-1: greedy fallisce (non puoi spezzare) → serve DP.
  • Huffman: codici a lunghezza variabile (prefix-free). Costruisci bottom-up: estrai ripetutamente i 2 caratteri meno frequenti, fondili in un nodo (somma frequenze). Min-heap → O(n log n).
  • Resto in monete: greedy (prendi sempre la moneta più grande) è ottimo solo per certi sistemi (es. €). Controesempio: monete {1,3,4}, resto 6 → greedy 4+1+1=3 monete, ottimo 3+3=2.

06bProgrammazione dinamica (DP)

DP = risolvi ogni sottoproblema una volta sola e memorizza il risultato (tabella). Serve optimal substructure + sottoproblemi sovrapposti.

Ricetta in 5 passi

  1. Definisci il sottoproblema (es. L(j) = LIS che finisce in aⱼ).
  2. Scrivi la ricorrenza (scelta tra le opzioni dei sottoproblemi).
  3. Casi base.
  4. Riempi la tabella bottom-up.
  5. Ricostruisci la soluzione ripercorrendo le scelte.

DP vs Greedy: il greedy decide subito e non torna indietro; la DP considera tutte le scelte e tiene la migliore. DP vs D&C: in D&C i sottoproblemi sono disgiunti, in DP si sovrappongono (→ memorizza).

Ricorrenze del corso

ProblemaRicorrenzaTabella
LISL(j) = 1 + max{ L(i) | i<j, a[i]<a[j] }O(n²)
Weighted activityOPT[i] = max( wᵢ + OPT[p(i)], OPT[i−1] )O(n)
Knapsack 0-1K(w,j) = max( K(w,j−1), vⱼ + K(w−wⱼ, j−1) )O(n·W)
Edit distanceE(i,j) = min( 1+E(i−1,j), 1+E(i,j−1), diff(i,j)+E(i−1,j−1) )O(n·m)

Dettagli utili

  • LIS ⟨5,2,8,6,3,6,9,7⟩ → L = [1,1,2,2,2,3,4,4] → lunghezza 4 (es. ⟨2,3,6,9⟩). Ricostruisci risalendo dai predecessori.
  • Weighted activity: ordina per finish time; p(i) = ultima attività compatibile prima di i. Case 1 = prendo i, Case 2 = la scarto.
  • Knapsack 0-1: tabella (W+1)×(n+1); diff = prendo / non prendo l'oggetto j. Ricostruisci confrontando K(w,j) con K(w,j−1).
  • Edit distance: diff(i,j)=0 se i caratteri coincidono, altrimenti 1 (sostituzione). Operazioni: insert / delete / match-or-substitute. cat→cut = 1.
  • Perché non basta la ricorsione naïve: ricalcola gli stessi sottoproblemi (Fibonacci/Pingala esponenziale) → la memoization/tabella lo rende lineare/polinomiale.

!Errori classici da evitare

  • Parafrasare il codice invece di dire cosa calcola.
  • Greedy su knapsack 0-1 — funziona solo nel frazionario.
  • Dijkstra con pesi negativi — usa Bellman-Ford.
  • Confondere O e Θ (O = limite superiore, Θ = stretto).
  • «NP = impossibile» — significa certificato verificabile in poly.
  • Visitare tutto il BST quando puoi potare il range.
  • Build-Max-Heap = O(n), non O(n log n).
  • Dimenticare l'analisi di complessità alla fine di ogni algoritmo.
  • Topological sort su grafo con cicli — vale solo sui DAG.
  • BST degenere — su dati ordinati l'altezza è Θ(n), non log n.
