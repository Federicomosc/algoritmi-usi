Riassunto ultra-semplificato di tutto il corso. Una riga = un concetto. Leggilo la sera prima e la mattina dell'esame — poi fai 2–3 esercizi dal final.

Come usarlo

Non studiare solo questo file: serve a richiamare ciò che già sai. Se un punto non ti dice niente, apri il capitolo completo dall'indice.

01Complessità

Θ = bound stretto · O = upper bound (≤) · Ω = lower bound (≥)
Ciclo annidato su n → spesso Θ(n²). Dividi per 2 a ogni livello → Θ(n log n).
P = risolvibile in tempo polinomiale · NP = certificato verificabile in polinomiale · NP-completo = il più difficile di NP
All'esame P/NP: in P → scrivi algoritmo. In NP → certificato + Verification(p, cert) polinomiale.

02Strutture dati

Array — accesso O(1), insert/delete O(n)
Lista — insert/delete O(1) se hai puntatore, accesso O(n)
Stack — LIFO · Queue — FIFO
Hash — medio O(1) search/insert; worst O(n)
Chaining = lista di collisioni · Open addressing = cerca slot libero (linear probing…)
Grafo sparso → lista adiacenze · denso → matrice O(V²)

03Ordinamento

AlgoritmoComplessitàNota veloce
Insertion sortΘ(n²)Ok per n piccolo o quasi ordinato
MergeSortΘ(n log n)Divide et impera, stabile, O(n) extra
QuickSortO(n log n) avg, O(n²) worstPartition + pivot; worst se pivot sempre min/max
HeapSortΘ(n log n)In-place, usa max-heap
Master theorem (semplificato): T(n)=aT(n/b)+f(n) → confronta f(n) con nlog_b a
Heap = array con padre ≥ figli (max-heap). Insert/extract → O(log n) con heapify.

04Alberi

BST — sinistra < radice < destra. Inorder = ordine crescente.
Insert — scendi fino a foglia, appendi. Delete — 0 figli: rimuovi; 1 figlio: sali; 2 figli: sostituisci con successor.
Range [a,b] — se key < a vai destra; se key > b vai sinistra; altrimenti conta + ricorsione.

Red-Black (5 regole)

  • Radice nera · foglie NIL nere · rosso → figli neri · stesso n° neri su ogni percorso
  • Insert → rotazioni + ricolora per ripristinare invarianti
B-tree — molti figli per nodo, altezza O(log n), per disco. Cerca/inserisci dividendo nodi pieni.

05Grafi

BFS — coda, livello per livello, shortest path su grafi non pesati. O(V+E)
DFS — ricorsione/stack, esplora in profondità. Colori WHITE/GRAY/BLACK. O(V+E)
Componenti connesse — ripeti BFS/DFS su vertici non visitati
MST — albero che collega tutti con peso minimo
Kruskal — ordina archi, prendi se non crea ciclo (Union-Find)
Prim — cresce albero da un vertice, scegli arco minimo verso fuori
Dijkstra — distanze minime, pesi ≥ 0. Relax archi da vertice con D minimo. O((V+E) log V) con heap.
NO Dijkstra con pesi negativi → usa Bellman-Ford (non chiesto spesso)

06Greedy & Programmazione dinamica

Quando usare cosa

Greedy ✓Serve DP ✗
Activity selection (non pesata)Weighted activity selection
HuffmanKnapsack 0-1
Fractional knapsackLIS (versione ottimale generale)
MST (Kruskal/Prim)Problemi con scelta che blocca il futuro
Greedy — scelta locale migliore + optimal substructure. Se fallisce → DP.
DP — 1) definisci sottoproblema 2) ricorrenza 3) casi base 4) tabella bottom-up 5) ricostruisci soluzione
Weighted activity — greedy earliest-finish NON ottimo. DP: OPT[i] = max peso compatibile + OPT[p(i)]
Knapsack 0-1 — K(w,j) = max con/senza oggetto j. Tabella (W+1)×(n+1)

★Pattern domande esame

Algo-X / Better-Algo-X
1) Cosa calcola? (1 frase, non riga per riga) · 2) Complessità worst case · 3) Idea miglioramento (sort, two pointers, counting array) · 4) Pseudocodice + nuova complessità
BST range / size
Poda rami impossibili. Con campo size → O(h). Non visitare tutto l'albero.
Grafi / BFS
Modella come grafo → BFS/DFS. Raggio minimo → binary search su r + Check(r) monotono.
DP esame
Identifica sottoproblema → ricorrenza → casi base → tabella → O(dimensione tabella).
Two pointers
Array ordinato → due indici i,j. Spesso dopo sort O(n log n) → totale O(n log n) o O(n).
Heap
Delete pos i = sposta ultimo in i + heapify up/down. O(log n).
P / NP decisionale
NP: certificato + verificatore polinomiale. P: algoritmo risolutivo esplicito.

!Errori da evitare

  • Parafrasare codice invece di dire cosa calcola
  • Greedy su knapsack 0-1 — funziona solo frazionario
  • Dijkstra con pesi negativi
  • Confondere O e Θ
  • NP = «impossibile» — significa certificato verificabile velocemente
  • Visitare tutto il BST quando puoi podare il range
  • Dimenticare analisi complessità alla fine di ogni algoritmo scritto
